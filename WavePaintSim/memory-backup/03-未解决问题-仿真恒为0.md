## 三、★ 前任新查实的确凿 Bug：绘制侧与仿真侧 `stride` 口径不一致

### 事实

| 位置 | 代码 | `m_subStepCount = 0` 时的结果 |
|---|---|---|
| `js/feature-common.js:250` | `wpf.subSteps = () => Math.max(0, Number(dw && dw.m_subStepCount) \|\| 0)` | `subSteps = 0` → `stride = 1` ✅ 符合铁律 |
| `js/feature-common.js:367` | `wpf.stride = () => Math.max(1, wpf.subSteps() + 1)` | `stride = 1` ✅ |
| `js/sim-bridge.js:151` | `canvasSubSteps = () => Math.max(1, Number(dw?.m_subStepCount \|\| 1) \|\| 1)` | `subSteps = 1` → `stride = 2` ❌ **多算一格** |
| `js/sim-bridge.js:349` | `subSteps: Math.max(1, Number(dw?.m_subStepCount \|\| 1) \|\| 1)` | 对外报告 `1`，真实是 `0` ❌ |
| `js/sim-bridge.js:155` | `canvasEffectiveCount = () => canvasTimeSteps() * (canvasSubSteps() + 1)` | 长度算成 **2 倍** ❌ |

### 影响

- 绘制侧按 `stride = 1` 把主值写进下标 `step × 1`；
- 仿真侧按 `stride = 2` 去下标 `step × 2` 采样 → **采样点整体错位**。
- `canvasEffectiveCount()` 会把新建/追加信号的 `values` 长度撑成 `timeSteps × 2`，
  与画布真实长度不符，制造出「长度异常」的信号，进一步触发下面的兼容分支混乱。

### 为什么现在没炸（暂时）

`js/sim-bridge.js:161` `sampleMainValue()` 开头有兼容分支：

```js
if (rawValues.length <= timeSteps) {
  const v = rawValues[mainStep];      // 旧数据按下标直取
  return ...;
}
```

当 `m_subStepCount = 0` 时 `values.length` 恰好 = `timeSteps`，命中该分支走「直取」，
**碰巧绕过了错误的 stride**，所以结果暂时正确。

**但这是脆弱的**：只要出现以下任一情况，就会立刻错位：
- 用户把子步数设为 ≥ 1（此时 length > timeSteps，走 stride=2 分支，而真实 stride 是 subSteps+1）；
- 画布步数（`m_sampleCount`）与 `#sample-spin` 输入框不同步；
- 信号被 `canvasEffectiveCount()` 按 2 倍长度创建过一次。

### 建议修法（未实施）

`js/sim-bridge.js` 的 `canvasSubSteps()` 与 `readWaveDocument()` 里的 `subSteps` 字段，
应改为与 `feature-common.js` 一致的 `Math.max(0, ...)` 口径：

```js
function canvasSubSteps() {
  const dw = window.document_wave;
  return Math.max(0, Number(dw?.m_subStepCount) || 0);   // 允许 0
}
```

改完务必回归 `node tools/regression.mjs`，并**人工**在子步数 = 0 和 = 2 两种配置下各跑一次仿真对比。

## 五、未排除的嫌疑（按建议排查顺序）

### 嫌疑 A：端口根本没绑定上 → 激励全是「未绑定默认全 0」⭐ 最可能

`matchSignalsToPorts`（`js/sim.js:477`）只做**名字匹配**：
- 精确：`normalizeSignalName(signal.name) === normalizeSignalName(port.name)`
- 模糊：`a.includes(b) || b.includes(a)`（且排除 `role === "result"` 的信号）

如果画布上的信号名与 RTL 端口名**对不上**（含大小写、前缀、用户手动改名），
就会全部落到 `strategy:"unbound"`，`buildAutoTestbench:546-557` 给它们生成**全 0 激励**，
DUT 输入恒 0 → **输出恒 0**。这与症状完全吻合。

> ⚠ 特别注意 `fuzzy` 分支的 `a.includes(b) || b.includes(a)`：
> 短路径名会误配，例如端口 `d` 会匹配上信号 `data`、`addr`、`valid` 中的任意一个（取 find 的第一个）。
> 一旦误配，多个端口可能拿到同一个错误信号。

**验证方法**：仿真面板里有 TB 预览，`buildTbPreview()`（`js/sim-bridge.js:437-440`）会打印：
```
bindings: N
<port> -> <signal> (name | fuzzy | unbound | unbound-default)
```
**直接肉眼看每个输入端口后面是不是 `<unbound>`。** 全是 unbound 就是这个问题。

### 嫌疑 B：画布波形压根没读出来（全 x）→ 兜底成 0

`readWaveDocument` 若取到的 `values` 全是 `-1`（x），则 `fromNativeBitValue(-1)` → `"x"`，
`formatVerilogValue("x")` → `1'bx`，DUT 输入为 x → 输出为 x 或 0。

可能与**嫌疑 A 的 stride bug**叠加：`canvasEffectiveCount()` 把长度撑成 2 倍后，
`sampleMainValue` 的兼容分支失效，采样到未初始化的下标（全是 x）。

### 嫌疑 C：$dumpvars 范围 / VCD 里根本没有 DUT 输出

`buildAutoTestbench:535-536`：
```verilog
$dumpfile("wave_out.vcd");
$dumpvars(0, tb);
```
`$dumpvars(0, tb)` 递归 dump 整个 tb，理论上包含 dut 输出。

但如果后端 `iverilog` 没正确生成/找到 `wave_out.vcd`，或 VCD 为空，
`parseVcd` 返回空 signals，则 `vcdToProjectOutputs` 的 `signals` 为空 →
界面上看到的「全 0」其实是**兜底/占位输出**，而非真实仿真结果。

**验证方法**：确认后端返回的 VCD 文本非空。可在 `runSimulation()` 里
（`js/sim-bridge.js:445` 之后）临时 `console.log` 出 VCD 原文，
或在浏览器 DevTools 的 Network 面板看 `/api/sim` 响应体。

### 嫌疑 D：`#sample-spin` 与画布实际步数不同步

`canvasTimeSteps()`（`js/sim-bridge.js:132-145`）优先读 `#sample-spin` 输入框，
回退 `m_sampleCount`，再回退信号最大长度，最后兜底 24，并 `Math.max(4, steps)`。

若输入框可见值与实际画布不一致（例如 feature-resize 改了步数但没同步输入框），
`timeSteps` 会算错 → `sampleTimes` 错位 → 采样到错误的时刻 → 表现就是「值不对 / 恒 0」。

### 嫌疑 E：TB 的 `$finish` 时机早于输出更新

`js/sim.js:589`：
```js
lines.push(`    #${Math.max(1, timeStep - prevTime)} $finish;`);
```
若 `prevTime >= timeStep`，则退化为 `#1 $finish`，仿真在第 1 个时间单位就结束，
DUT 来不及产生任何输出 → **全 0**。

当 `events` 的 `time` 上界（≈ `values.length - 1`）大于 `timeSteps` 时会触发，
而这正是 **stride bug 导致 values 长度翻倍** 后的直接后果。
→ 嫌疑 E 与第三节的 stride Bug 是**同一根因的两种表现**。

## 六、给接替 AI 的分步排查清单

> 前任在本环境**无法启动 GUI**（PowerShell `Start-Process` 起的 `WavePaint.exe`
> 会在工具调用结束时被沙箱回收），所以以下步骤需要**在真实浏览器里执行**。

### Step 1 —— 二分区（最关键，5 分钟）

1. 打开 WavePaint，画一组明显的输入波形（例如 `clk` 方波 + `d` 在若干格翻高）。
2. 点「生成 TB / TB 预览」（`buildTbPreview`）。
3. **肉眼看生成的 TB 源码里的激励语句**：
   - 若所有输入都是 `xxx = 1'b0;` 且从不变化 → 问题在 **[1]~[3]**，跳 Step 2。
   - 若激励正确反映了画的波形 → 问题在 **[5]~[9]**，跳 Step 4。
4. 同时看 `bindings:` 那几行，确认每个输入端口的 strategy 不是 `unbound` / `unbound-default`。

### Step 2 —— 查端口绑定

浏览器控制台执行：
```js
const dw = window.document_wave;
console.log("画布信号:", dw.m_signals.map(s => ({ name: s.name, len: s.values?.length, head: s.values?.slice(0,8) })));
console.log("子步数 m_subStepCount =", dw.m_subStepCount, " 样本数 m_sampleCount =", dw.m_sampleCount);
console.log("步数输入框 #sample-spin =", document.querySelector("#sample-spin")?.value);
```
对照 RTL 的端口名，确认**名字能精确对上**。对不上就是嫌疑 A。

### Step 3 —— 验证 stride 口径（确认第三节的 Bug 是否真的在作祟）

```js
const dw = window.document_wave;
const n = dw.m_subStepCount;
console.log("真实 stride 应为 =", n + 1);
console.log("feature-common 认为 =", window.__wpf.stride());
console.log("(sim-bridge 内部用 canvasSubSteps()+1 =", Math.max(1, n || 1) + 1, ")");
const s0 = dw.m_signals[0];
console.log("values.length =", s0?.values?.length, " 画布步数*stride 应为 =", dw.m_sampleCount * (n + 1));
```
若 `values.length` ≠ `m_sampleCount × (m_subStepCount + 1)`，**数据模型已经被破坏**，
这就是恒 0 的直接原因，需先修 stride 口径再谈其它。

### Step 4 —— 查后端与 VCD

浏览器 DevTools → Network → 点「Sim」→ 看 `/api/sim` 的响应：
- 响应里有没有 VCD 文本 / 有没有 stderr？
- 若后端报错（iverilog 编译失败），响应里通常有编译日志，先解决编译错误。
- 若 VCD 非空，把它存下来，用 Node 单独跑一遍解析：
  ```bash
  node -e "import('./js/sim.js').then(m=>{const r=m.parseVcd(require('fs').readFileSync('wave_out.vcd','utf8'));console.log('tmax',r.tmax);console.log(r.signals.map(s=>[s.name,s.width,s.steps.length]))})"
  ```
  看 `tmax` 是否 > 0、signals 是否非空、`steps.length` 是否 > 1。
  - `tmax = 0` 或 `steps.length = 1` → 仿真没跑起来 / TB 立刻 `$finish`（嫌疑 E）。
  - signals 里**没有 DUT 输出** → `$dumpvars` 或后端问题（嫌疑 C）。

### Step 5 —— 修完必回归

```bash
node tools/regression.mjs            # 期望 21/21
node --check js/sim-bridge.js && node --check js/sim.js
.\build.ps1                          # 期望 csc exit: 0
```
并且**分别在 子步数=0 和 子步数=2 两种配置下各跑一次仿真**，确认两者结果一致且非全 0。
