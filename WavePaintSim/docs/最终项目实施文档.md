## 1. 数据模型与运行链路（必读）

### 1.1 数据模型

```
document_wave
 ├─ m_sampleCount   主步数（UI「步数」#sample-spin，默认 30）
 ├─ m_subStepCount  子步数（UI「子步数」#substep-spin，默认 1）
 └─ m_signals[]     Signal：name/type(Bit=0|Vector=1|BlankRow=2)/values/labels/...

values.length = m_sampleCount × (m_subStepCount + 1)
主值下标 = 主步号 × stride（stride = 子步+1），如 30步/子步1 → stride=2 → 主值下标 0,2,4,...
子步下标 = 主值下标 + 1..+stride-1（如 1,3,5,...）

位值编码（Bit values 为数字）：0=低 1=高 -1=未定义(x) 2=z 3=u 4=d；Vector values 为字符串
坐标映射 window.mapCanvasPosition(x,y) → { signalIndex, signalSampleIndex(★values下标), mainStep, signalDivisor(=stride), ... }
```

### 1.2 仿真链路（点「Sim」后发生什么）

```
readWaveDocument()      读画布信号 → project 信号（★采样主值）
buildAutoTestbench()    匹配端口 → 生成 TB（clk 优先、全阻塞赋值）
fetch POST /api/sim     本地 HttpListener → iverilog 编译 → vvp 仿真 → VCD
vcdToProjectOutputs()   解析 VCD → outputs
replaceInjectedOutputs()把 q 等输出注入画布
```

### 1.3 关键现状（实测）

| 环节 | 现状 |
|---|---|
| `feature-draw.js` TimeGen 绘制 | 修复语法后可用；写整主步（默认整步粒度）；**默认无工具激活时不接管**（`currentTool()!=='paint'` 就 return）|
| `readWaveDocument` 采样 | 只采主值下标；**无兜底**（主值 x 时不会取步内确定值）|
| `matchSignalsToPorts`（sim.js）| 未匹配端口**共用第一个 fallback 信号**（BUG-002）|
| TimeGen 绘制撤销 | **不压撤销栈**（BUG-003）|
| 侧栏乱码 | 已修复（index.html:400,403 为「仿真」）|

## 2. 问题 X：仿真结果一直为 0（用户实测，最高优先级）

### 2.1 症状

用户绘制波形后点「Sim」，结果（如 counter 的 q）**一直是 0**（或 x）。已确认不是单一原因，是**多层根因叠加**。

### 2.2 完整根因链（每层都可能导致 0，需全部修复）

**层 1（已修，防回归）**：`feature-draw.js` 曾被另一 AI 写出 4 处 `''...''` 双引号**语法错误** → 模块整体加载失败 → TimeGen 绘制消失。已修复，但请保持字符串用**单引号**。

**层 2（核心，未修）**：TimeGen 接管条件过严 + 原版绘制写"子步值"。
- `feature-draw.js onMouseDown`：`if (wpf.currentTool() !== 'paint') return;`。
  - **默认情况下没有任何工具按钮有 `.active` 类**（实测 `currentTool()===null`），所以**用户不手动点「画笔」时，TimeGen 完全不接管**。
- 不接管时，用户点击走**原版绘制**：写入 `signalSampleIndex`（鼠标所在下标）。当用户点在主步的"右半"子格时，写入**奇数下标（子步值）**（如 x=200 → sampleIdx=5）。
- `readWaveDocument` 只采样**主值下标（偶数 = 主步×stride）** → 画在奇数下标的值**采不到** → 该步为 x/0 → 仿真 0。

**层 3（未修）**：`readWaveDocument` **无兜底**。即使主值下标是 x、但同主步其它下标有确定值，也不取。若用户用子步粒度画了值（奇数下标），仿真仍读不到。

**层 4（未修）**：BUG-002 —— 若 RTL 端口数 > 画布信号数，未匹配端口**共用第一个信号**的波形，激励静默错误（可能把 clk 驱动到别的端口）。

### 2.3 修复方案（必须全部实施）

#### 修复 X-1：TimeGen 默认接管（无激活工具视为画笔）—— ✅ 已实施

`js/feature-draw.js` 的 `onMouseDown` 里，把工具判断放宽（已改）：

```js
// 当前激活工具；无激活工具时按"画笔"处理（与原版默认画笔一致）
function activePaintTool() {
  const t = wpf.currentTool();
  return t === null ? 'paint' : t;   // null/无激活 = 默认画笔
}
// onMouseDown 中：
if (activePaintTool() !== 'paint') return;
```

同时确认：橡皮擦（erase）、选择（select）等**显式激活**的工具仍不被 TimeGen 接管（它们在 `currentTool()` 返回非 paint 时正常放行）。

> 注意：需要先确认原版默认工具。若原版默认确实是画笔，则此项等价于"无工具=画笔"；若原版默认是其它，则需在文档标注并让 TimeGen 在"无工具"时也接管（因为无工具时原版点击同样会绘制，行为应以"能画"为准）。

#### 修复 X-2：readWaveDocument 兜底采样（核心保障）—— ✅ 已实施

`js/sim-bridge.js` 的 `readWaveDocument()`：对每个主步，若主值下标为 x/空，则取该主步内**第一个非 x 的确定值**（已改为调用新增的 `sampleMainValue()`）：

```js
// 现状（约 320-335 行）
const values = Array.from({ length: timeSteps }, (_, cell) => {
  const direct = stride <= 1 ? cell : cell * stride;
  const raw = rawValues.length > timeSteps ? rawValues[Math.min(direct, rawValues.length - 1)] : rawValues[cell];
  return width <= 1 ? fromNativeBitValue(raw) : normalizeVectorValue(raw, width);
});
```

改为带兜底的版本：

```js
function sampleMainValue(rawValues, stride, mainStep, timeSteps) {
  const start = mainStep * stride;
  // 旧信号（长度=主步数）直接直取
  if (rawValues.length <= timeSteps) {
    const v = rawValues[mainStep];
    return (v === -1 || v === undefined || String(v ?? '').trim() === 'x') ? -1 : v;
  }
  const group = [];
  for (let k = 0; k < stride; k += 1) {
    const idx = start + k;
    if (idx < rawValues.length) group.push(rawValues[idx]);
  }
  // 主值优先；主值非 x 用主值，否则取该步第一个确定值，否则 x
  const main = group[0];
  if (main !== -1 && main !== undefined && String(main ?? '').trim() !== 'x') return main;
  for (const v of group) {
    if (v !== -1 && v !== undefined && String(v ?? '').trim() !== 'x') return v;
  }
  return -1;
}
```

`values` 生成处改为调用 `sampleMainValue(...)`。这样无论用户画在主值还是子步下标，仿真都能采到该步的实际值。

#### 修复 X-3：BUG-002 未绑定端口不再共用 fallback —— ✅ 已实施

`js/sim.js` 的 `matchSignalsToPorts`（477-489）：把第 486 行的 `find()` fallback 改为（已改：fuzzy + unbound，`buildAutoTestbench` 对 unbound 输入生成默认 0）：

```js
return (ports || []).map((port) => {
  const key = normalizeSignalName(port.name);
  const exact = signalMap.get(key);
  if (exact) return { port, signal: exact, matched: true, strategy: "name" };
  // 模糊匹配（如 rst_n <-> rstn）
  const fuzzy = (signals || []).find((s) => {
    if (s.role === "result") return false;
    const a = normalizeSignalName(s.name), b = key;
    return a && b && (a.includes(b) || b.includes(a));
  }) || null;
  if (fuzzy) return { port, signal: fuzzy, matched: true, strategy: "fuzzy" };
  return { port, signal: null, matched: false, strategy: "unbound" };   // ★ 不再共用
});
```

配套：
- `buildAutoTestbench` 对 `signal == null` 的**输入端口**：用 `createSignalFromPort(port, null, "stimulus", timeSteps)` 生成一个**独立的全 0 默认激励**（避免保持 x 导致仿真 x；也避免共用）。输出端口保持 wire。
- UI 绑定提示（`sim-bridge.js` `buildTbPreview` / `runSimulation` 的 module-preview）：未绑定端口标注 `⚠ 未绑定(默认0)`。

#### 修复 X-4（可选增强）：激励全 x 时给默认值

若用户**完全没画**某信号（全 x），仿真会 x 传播。可选：`readWaveDocument` 或 `buildAutoTestbench` 对全 x 的输入端口默认按 0 处理，并提示。此项可选，先做 X-1~X-3。

## 5. 常见坑（速查，务必遵守）

1. csc 是 .NET 4.0（C# 4.0）：改 C# 禁止 `out int x`、`??=`、switch 表达式等 C#7+ 语法。
2. 改 JS/HTML 必须重建 exe；构建前先杀 WavePaint（exe 被占用报 CS0016）。
3. 禁止改混淆核心；一切走 `window.document_wave` / `window.mapCanvasPosition` / 事件接管。
4. 数据模型铁律：`values.length === 步数×(子步+1)`；绘制默认写整主步。
5. 位值编码：Bit=数字(0/1/-1/2/3/4)，Vector=字符串。
6. **字符串用单引号 `'...'`，严禁 `''...''`**（本次仿真 0 的根因）。
7. 页面不可见时 `requestAnimationFrame` 不执行（feature-measure overlay）。
8. `#sample-spin`/`#substep-spin` 已由 `feature-resize.js` 接管，勿重复拦截。
9. `sim-bridge.js` 的 DOM id 勿改（只改样式）。
10. 中文一律 UTF-8 无 BOM；用 `[System.IO.File]::WriteAllText(path, text, (New-Object System.Text.UTF8Encoding($false)))` 写，别用 `Set-Content`（GBK 乱码）。
11. 页面不可见时 Playwright mouse 事件不可靠——**验证绘制/仿真用 `dispatchEvent`**（可触发 document 捕获阶段监听器），或确保页面可见。
12. 原版点击绘制需要真实（isTrusted）事件；dispatchEvent 无法触发原版绘制——所以**用 dispatchEvent 只能验证 feature 模块（捕获阶段）逻辑**，原版路径需可见页面人工确认。
