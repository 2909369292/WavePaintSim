# 功能需求书：波形框选编辑（总线 + 位信号）

> 读者：下一位负责 WavePaintSim 的实现 AI。
> 目的：把「框选编辑」这一功能需求定义清楚，让你无需再向用户追问即可开工。
> 作者：Copilot（2026-09-01）。本文档对应规划项 **7.1 总线编辑框选**、**7.7 整步/子步对总线生效**、**7.8 选择模式编辑总线** 的**补全与重做**。
> ⚠ 本文档是**需求定义**，不是实施规格——实现细节（函数名、行号）由实现者自行决定，但**交互行为、边界、验收标准必须照此执行**。

---

## 0. 一句话目标

**让用户能在"编辑（默认画笔）工具"下直接框选一段波形来编辑**：总线框选后输入任意数值写入，位信号框选后输入 `1/0/x/z` 写入；框选写入的**粒度跟随顶部「整步 / 子步」开关**；框选操作**可撤销**。

---

## 1. 背景与现状（实现者必读）

### 1.1 当前已实现的功能（`js/feature-select.js`，选择工具框选）

现状是**只有在「选择工具」下**才可框选：

1. 点击工具栏「选择」（`#tool-select`）→ 按住左键拖动 → 画布上出现蓝色虚线框（跨多信号 × 多格子）。
2. 松开鼠标 → 在鼠标位置弹出浮动工具条 `#wpf-batch-bar`，包含按钮：
   - **设 1 / 设 0 / 设 x / 翻转**（批量作用于选区内的 Bit 与 Vector 信号）
   - **复制 / 粘贴**（选区复制，按信号行对齐粘贴）
   - **输入值**（文本框 + 按钮）：对选中范围的 **Vector（总线）** 写任意数值（支持 `10` / `0xA` / `0b1010` / `8'hA5` / `x` / `z`）；对 **Bit** 信号只接受 `1` / `0` / `x` / `z`
   - **取消**
3. Escape / 点击工具条外 / 切工具 → 工具条关闭，选区清除。

### 1.2 现状与用户期望的差距（为什么"理解错了"）

| # | 用户反馈 | 现状 | 差距 |
|---|---|---|---|
| 1 | 「总线编辑框选的功能尚未实现」 | 框选只在**选择工具**下可用 | 用户在**编辑（画笔）工具**下没法框选总线，期望的"编辑模式下框选总线改值"没实现 |
| 2 | 「线性信号像框选总线那样的功能还没有实现」 | Bit 信号也能框选，但只能写 `1/0/x`，且需先切选择工具 | Bit 信号在**编辑工具**下也能像总线一样"框选→输入值" |
| 3 | 「总线框选的力度并没有实现」 | 写入是**逐下标（子步粒度）**，无视顶部「整步/子步」开关 | 框选写入应**跟随顶部粒度开关**（整步=整主步含子格，子步=单个子格） |
| 4 | 「现在做了一个框选，但似乎理解错了」 | 形态是"选择工具 + 浮动工具条" | 期望形态是"**编辑工具下直接框选**"，工具条/输入框是辅助 |

### 1.3 必须遵守的架构约束（沿用既有纪律）

- **禁止修改** `js/wavepaint.63e6dade.js`（混淆核心）。所有增强走**新 feature 模块 + 捕获阶段事件接管 + `stopImmediatePropagation`**。
- **数据模型铁律**：`sig.values.length === m_sampleCount × (m_subStepCount + 1)`；`stride = m_subStepCount + 1`；主值下标 = `主步 × stride`。
- **写入统一走** `wpf.writeValue(sig, mainStep, subStep, value)`（`feature-common.js` 已有，整步/子步双支持，千万别绕过它直接写裸下标）。
- **撤销**：批量修改前调 `wpf.pushUndoSnapshot()`（已委托核心，自带 100 条上限）。
- **改 JS 必须重建 exe**（`build.ps1`）并跑 `regression.mjs` + `e2e-sim.mjs`。

## 3. 详细需求

### R1 — 编辑（画笔）工具下框选总线并输入值 【P0】

**用户故事**：我在默认编辑工具下，想改一段总线的值。我不希望先切到「选择工具」。我直接在总线波形上按住左键拖过一段范围，松开后就能输入一个数值（如 `0xA5`），这段范围立刻变成该值。

**交互流程**：

1. 当前工具为**画笔/默认编辑**（`wpf.currentTool()` 返回 `'paint'` 或 `null`）。
2. 鼠标按下命中 **Vector（总线）信号**的波形区（`wpf.mapAt(x, y)` 返回 `{ signalIndex, signalSampleIndex, clickedOnName:false }`，且 `m_signals[signalIndex].type === SignalType.Vector`）。
3. 按住左键**横向拖动** → 出现蓝色虚线框（沿用选择工具的 overlay 绘制，跨当前信号行的一段格子）。
4. 松开 → 弹出浮动输入条（见 R4），输入框聚焦，光标停在框选起点。
5. 输入值（支持 `10` / `0xA` / `0xA5` / `0b1010` / `8'hA5` / `x` / `z` / 下划线 `1_0`）→ 回车或点「确定」→ 该段总线按 R3 粒度写入该值 → 刷新标签（`wpf.refreshBusLabels`）→ 重绘。
6. 按 Escape 或点外部 → 取消，选区清除。

**关键规则**：
- 总线信号在编辑工具下**拖动 = 框选**（不是画波形——总线本来也没有"画"的语义，天然不冲突）。
- 总线信号上**单击（不拖动）**：保持原版行为（选中信号 / 打开属性），不弹输入框。
- 框选**纵向跨行**：允许，但见 R2/R6——若框到 Bit 信号，输入值对 Bit 只取 `1/0/x/z`（或按 R2 处理）。
- **不动选择工具**：选择工具下的框选与工具条完整保留（现状即正确，只是补粒度 R3）。

### R2 — 编辑工具下框选位(Bit)信号并输入值 【P0】

**用户故事**：我想把一段 Bit 信号从 `0101` 改成 `1111`（或改成 x）。像框选总线一样，我在 Bit 波形上拖过一段，输入 `1`（或 `1111`），这段就变成该值。

**交互流程**：

1. 编辑工具下，在 **Bit 信号**行上按住左键拖动 → 框选一段格子。
2. 松开 → 浮动输入条（同 R4），输入框接受 `1 / 0 / x / z`（可输入多位，如 `1111`，超出部分忽略、不足部分按最后一位填充或保持——见"边界规则"）。
3. 回车 → 该段按 R3 粒度写入。

**⚠ 与 TimeGen 绘制的冲突（关键设计决策）**：

编辑工具下 Bit 信号**普通拖动 = TimeGen 连续绘制**（现有 `feature-draw.js` 行为，上半画 1、下半画 0、拖动连绘）——这是用户已确认保留的功能，**不能破坏**。

因此 Bit 信号的框选需要**显式区分触发**，推荐以下机制（实现者可择一，但必须不破坏 TimeGen）：

- **方案 A（推荐）**：按住 **Shift + 拖动** = 框选；普通拖动 = 绘制。
  - Shift 已有"擦除写 x"语义（`feature-draw.js`）——需确认：若 Shift 已被占用，改用 **Ctrl+拖动** 或 **Alt+拖动** 作为框选修饰键。**实现者必须在浏览器实测当前 Shift 行为**，选择未被占用的修饰键，并在文档记录。
- **方案 B**：Bit 信号框选入口只放「选择工具」（现状）+ 增加一个**工具栏小按钮「框选编辑」**，点击后临时进入"框选模式"，此模式下拖动=框选、不绘制。
- **方案 C**：Bit 信号**双击**进入框选模式（进入后拖动=框选），再次点击画布或 Escape 退出。

> **推荐方案 A**（修饰键 + 拖动），最符合"像框选总线那样"的直觉；若修饰键与现有功能冲突则退到方案 B。
> **实现者在文档的"实现说明"里必须写明最终选择了哪个方案、为什么。**

**边界规则**（Bit 输入值）：
- 输入 `1` → 框选段全部写 1（按 R3 粒度）。
- 输入 `1010` → 从框选起点开始逐格写 1/0/1/0，超出框选长度截断；不足长度**循环重复**（`101` → `10110`）或保持原值（实现者二选一，推荐**循环重复**，更符合直觉）。
- 输入 `x` / `z` → 整段写 x / z。
- 输入其它字符 → 忽略该输入，工具条不消失但输入框标红（R9）。

### R3 — 框选写入粒度跟随顶部「整步 / 子步」开关 【P0】

**这是用户点名的「总线框选的力度」**。当前实现逐下标写（子步粒度）是错的，必须改为：

**规则**：
- 顶部粒度开关取值：`wpf.editGranularity()` 返回 **`'step'`**（整步，默认）或 **`'substep'`**（子步）。
- **整步（`'step'`）**：框选范围内每个被覆盖的**主步**，写该主步的**全部 `stride` 个格子**（主值下标 + 所有子格）。
- **子步（`'substep'`）**：只写框选范围内**实际覆盖到的单个格子下标**。
- **粒度开关的当前状态在框选写入那一刻读取**（不是框选开始时），因为用户可能在框选过程中切换。

**★ 实现捷径（重要）**：`wpf.writeValue(sig, sampleIndex, value)`（`feature-common.js`）**内部已经按当前粒度处理整步/子步**——`'step'` 时铺满该主步全部 stride 格、`'substep'` 时只写该下标，并会同步清掉 `clockMarkers`。因此**框选写入只需对每个覆盖下标调用一次 `wpf.writeValue(sig, i, value)` 即可，无需自己判断粒度**（见 §4.3）。

**数据一致性**：
- 写完整主步时，同时用 `wpf.syncSignalMeta(sig, values.length)` 保证 `labels / segmentStyles / driveStrengths / clockMarkers / waveDromColorCodes` 长度一致（主值写整步时这些数组对应格子也应是新值）。
- 写入后调用 `wpf.refreshBusLabels(sig)`（Vector）并 `wpf.scheduleRedraw()`。

**验收**：
- 子步=1（stride=2），整步模式框选 2 个主步 → `values` 4 个下标全变新值。
- 子步=1，子步模式框选 2 个主步 → 只变框选覆盖的 2 个下标，另 2 个子格保持。
- 子步=0（stride=1）时整步=子步，行为一致。

---

### R4 — 框选交互形态：虚线框 + 浮动工具条（含输入框） 【P0】

沿用现有 `feature-select.js` 的视觉与工具条，但**拆成可复用组件**（因为选择工具和编辑工具都要用）：

1. **虚线框 overlay**：把 `ensureOverlay / syncOverlaySize / drawMarquee / regionFromPoints / regionSignals` 从 `feature-select.js` **提取为公共模块**（建议 `feature-common.js` 或新 `feature-marquee.js`），供两个入口共用。
2. **浮动工具条** `#wpf-batch-bar`，包含：
   - 批量按钮：**设 1 / 设 0 / 设 x / 翻转**（Bit 与 Vector 均适用）
   - **输入框 + 确定**：总线输任意值；Bit 输 `1/0/x/z`
   - **复制 / 粘贴**、**取消**
   - 工具条标题行显示当前粒度：`整步` / `子步`（灰色小字），随顶部开关联动。
3. **输入框交互**：
   - 弹出后**自动聚焦**，`Enter` 确认、`Escape` 取消。
   - 输入非法值（R2/R9）时输入框红色描边 + tooltip 提示，不静默。
4. **关闭时机**：点击工具条外 / Escape / 切换工具 / 窗口失焦 → 关闭并清选区（现状 P3-1 已实现，复用）。

---

### R5 — 撤销 【P0】

- 每次框选批量写入（设 1/设 0/设 x/翻转/输入值/粘贴）**在写入前**调一次 `wpf.pushUndoSnapshot()`（只压一次，不是每格一次）。
- Ctrl+Z 整体回退该次框选写入；Ctrl+Y 重做。
- **验收**：框选输入值后 Ctrl+Z → 波形完整回到框选前；再 Ctrl+Y → 恢复。

---

### R6 — 与现有功能互不冲突 【P0】

| 现有功能 | 冲突点 | 解决 |
|---|---|---|
| TimeGen 绘制（`feature-draw.js`，paint 下 Bit 拖动=画） | 编辑工具下 Bit 拖动既可能画也可能框选 | 按 R2 方案 A（修饰键）区分；Vector 无冲突（拖动=框选） |
| 选择工具框选（`feature-select.js`） | 两套框选并存 | 提取公共组件（R4），选择工具入口行为不变，仅补 R3 粒度 |
| 快捷键（`feature-shortcuts.js`）：方向键绘制、1/0/X/Z/U/D | 输入框内按键不应触发全局快捷键 | 输入框 keydown 必须 `stopPropagation()`（现状 `showBar` 已对 Enter/Escape 处理，需覆盖全部按键） |
| 原版单击选中 / 属性面板（混淆核心） | 编辑工具下单击 Vector 不应弹输入框 | 仅**拖动 > 5px** 才进入框选；单击放行原版 |
| 拖动锁定信号（TimeGen 行为） | 编辑工具下跨行拖动 | 框选允许跨行（R1 允许）；TimeGen 绘制保持单行锁定（现状） |

**监听器注册顺序纪律**：所有捕获阶段监听器必须**在 `feature-common.js` 之后注册**（index.html 引入顺序）；多模块同事件时，先注册先执行——框选模块与绘制模块的 mousedown 处理必须**互斥短路**（一个接管后 `stopImmediatePropagation`，另一个必须能识别并 return）。

---

### R7 — 输入时波形实时预览 【P1】

- 输入框内容合法时，框选区域的波形**实时**以该值绘制（低透明度预览色），回车确认后实写。
- 实现：输入 `input` 事件 → 解析 → 若合法，在 overlay 上以半透明色绘制该段的新值波形；非法则显示红色边框。
- 验收：输入 `0xA5` → 框选段立即半透明显示 `10100101` 波形 → 回车后实写。

---

### R8 — 总线值进制联动 【P1】

- 输入 `0xA5`（hex）或 `10100101`（bin）或 `165`（dec）都接受；写入后标签按**信号当前 radix** 显示（`wpf.busRadixLabel` 已实现）。
- 验收：总线 radix=hex，输入 `165` → 波形标签显示 `A5`；radix=bin，输入 `0xA5` → 标签显示 `10100101`。

---

### R9 — 非法输入与空选区提示 【P2】

- 输入非法 → 输入框红框 + tooltip「仅支持 10 / 0xA / 0b1010 / 8'hA5 / x / z」。
- 框选完全落在波形区外（`regionFromPoints` 返回 null）→ 不弹工具条，状态栏（`#sim-status` 或画布上方）提示「未选中有效波形区域」。
- 验收：以上两种场景均有可见反馈，无静默失败、无控制台异常。

### 4.3 写入核心（R1/R2/R3 的伪代码）

**`wpf.writeValue(sig, sampleIndex, value)` 内部已按当前粒度处理整步/子步**（`'step'` 铺满主步、`'substep'` 只写单格，并清 clockMarkers），所以写入循环非常简单：

```js
function applyValueToRegion(region, rawValue) {
  wpf.pushUndoSnapshot();
  for (const { sig } of regionSignals(region)) {
    const isVec = sig.type === window.SignalType.Vector;
    const value = isVec ? normalizeVectorValue(rawValue, vectorWidth(sig))
                        : normalizeBitInput(rawValue);          // 1/0/x/z 或位串
    if (value === null) continue;                               // 非法，R9 提示
    for (let i = region.sampleStart; i <= region.sampleEnd; i++) {
      wpf.writeValue(sig, i, value);   // ★ 粒度由 writeValue 内部按当前开关处理
    }
    if (isVec) wpf.refreshBusLabels(sig);
  }
  wpf.scheduleRedraw();
}
```

> 若 `normalizeVectorValue`（`model.js`）对单个下标返回的是**位串**（如 `'10100101'`），而 `writeValue` 直接写入该字符串——请确认这是 `refreshBusLabels` 期望的格式（现状 `applyCustom` 就是这样做的，直接复用其写法即可）。
