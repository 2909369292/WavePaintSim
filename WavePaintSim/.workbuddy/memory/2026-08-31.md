## 二、P1 常见信号预填典型波形

`js/sim.js` 新增：
- `typicalWaveform(port, timeSteps)`
  - clock → 方波 `0101...`（半周期 1 时间单位，占空比 50%）
  - 低有效复位 rst_n → 前 2 格 `0`（复位），之后 `1`（释放）
  - 高有效复位 rst → 前 2 格 `1`，之后 `0`
  - 其余**返回 null**，保持未定义(x) —— 不臆造用户数据
- `createPortStimulus(port, timeSteps)`（createSignalFromPort + typicalWaveform）

⚠ **教训**：一开始我把预填只写在 `addPortSignalsToCanvas` 里，
e2e 的用例模拟（applyUserFlow）没同步，**测试显示"全 x"才发现**。
已把逻辑抽成 `createPortStimulus` 作为单一真相源，两边共用。
**用例模拟必须与真实实现共用同一函数，否则测了个寂寞。**

## 三、P2 未绑定告警与结果诊断

`js/sim.js` 新增 `diagnoseSimulation(outputs, bindings)`，返回中文提示数组：
- 未绑定输入端口 → 点名列出，并说明已按默认电平驱动
- 激励全 x → 点名列出信号
- 输出恒 0 → 提示复位可能一直有效
- 输出恒 x → 提示缺少复位释放沿

接入 `sim-bridge.js` 的 `buildTbPreview()` 与 `runSimulation()` 结果区 + status 栏。

## 四、P3 默认浅色主题

探明机制（详见 MEMORY.md「主题机制」一节）：
- 主题 = `body.dark` class；CSS `:root` 默认本就是浅色，深色只是覆盖
- **混淆核心是顶层脚本（非 IIFE）**，`applyTheme` 是全局函数且会持久化
- `WavePaintSkins`（Black/Sunset/Forest，全深色系）只影响波形颜色，与背景无关

实现在 `js/feature-common.js`：启动时调 `window.applyTheme('light')`，
用 `localStorage` 标记 `wpf.defaultLightThemeApplied` **只干预一次**
（改默认值而非锁死主题，用户后续选择一律尊重），
并用 MutationObserver 观察 10s 窗口防止被核心异步改回深色。

## 五、P4 收紧 fuzzy 端口匹配

旧实现 `find(s => a.includes(b) || b.includes(a))` 会让端口 `d` 误配到
`data`/`addr`/`valid`，且同一信号可被多个端口共用。改为：
1. 单字符端口名（d/q 等）**不参与**模糊匹配
2. 长度比 < 0.3 不配对
3. 每个信号只能被一个端口占用（一对一 `claimed` 集合），候选中取最相似者
4. 精确匹配仍优先

`sys_clk→clk`、`enable→en` 这类命名风格差异照旧可匹配（已回归验证）。
