## 深度静态探测推翻了首轮 3 条结论（重要教训）

1. ~~HiDPI 叠加层错位~~ → 核心中 `devicePixelRatio` / `setTransform` 出现 **0 次**，无 DPR 缩放。降级为"隐式尺寸假设"隐患。
2. ~~mapCanvasPosition 越界返回 null 导致 TypeError~~ → null **只在** `if(!document_wave||!canvas)return null` 时返回；几何越界返回**全 -1 哨兵对象**，不会崩。
   但顺带查出真问题：`regionFromPoints` 的 `Math.max(0,...)` 把 -1 静默夹成 0 → 选区被静默扩大到信号 0。
3. ~~structuredClone 丢失 Signal 原型~~ → 核心自己的快照就用 `JSON.parse(JSON.stringify(...))`，撤销栈里本来就是普通对象。真正的问题是手写版**没有 100 条上限裁剪**。

### ★ 本次审计最大发现：核心自带 `pushUndoSnapshot()`

- `WaveDocument.prototype.pushUndoSnapshot()`，核心内部调用 **32 次**。
  自带撤销栈上限 100（`if (length > 100) shift()`）+ 清空 `m_redoStack`。
  → `feature-common.js` 的 `wpf.pushUndoSnapshot()` 应改为**委托**它，而不是自己实现一份。
  ⚠ 两者**同名**（`document_wave.pushUndoSnapshot` vs `__wpf.pushUndoSnapshot`），极易混淆。

### ★ 本次踩到 / 发现的关键事实（避免重犯）

   真实依赖 —— 若没及时发现，运行时整个仿真链会崩。做法：遍历 `js/*.js` 的
   `from "./x.js"` 求闭包，再和 `index.html` 的 `src="js/..."` 取并集。
2. **根目录的 `wavepaint.63e6dade.js` 不是重复副本，是打补丁前的原始版本。**
   与 `js/` 下版本唯一差异：`document_wave=new WaveDocument()` →
   `document_wave=window.document_wave=new WaveDocument()`。
   这个 `window.` 前缀是所有 feature 模块能工作的前提。已移存 `attic/core-original/` 并写 README 警示。
3. **项目已在父仓库 `D:/Files/Code/波形` 中被跟踪（72 个文件）。** 此时执行 `git init`
   会形成嵌套仓库、反而让文件脱离版本控制 —— **不要执行**。P3-4 的「仓库无 .git」实际已满足。
   另：`docs/` 目前**未被跟踪**；`WavePaint.exe`（21MB 构建产物）**已被跟踪**。
4. **核心已自带 F9 需要的一切**：`window.Radix={Hexadecimal:0,Decimal:1,Binary:2}`、
   `WaveDocument.prototype.valueToLabel(value, radix)`、`Signal.radix` 字段，
   且属性面板里已有进制切换（偏移 1354242~1355155）。工具栏那个只是"更好找的入口"，

### 本轮（只读）新查实的确凿 Bug：两侧 stride 口径不一致

| 位置 | 代码 | `m_subStepCount=0` 时 |
| --- | --- | --- |
| `js/feature-common.js:250` `wpf.subSteps()` | `Math.max(0, ...)` | `subSteps=0` → `stride=1` ✅ |
| `js/feature-common.js:367` `wpf.stride()` | `subSteps()+1` | `stride=1` ✅ |
| `js/sim-bridge.js:151` `canvasSubSteps()` | `Math.max(1, ...)` | `subSteps=1` → `stride=2` ❌ **多算一格** |
| `js/sim-bridge.js:349` `project.subSteps` | `Math.max(1, ...)` | 对外报错 `1`，真实 `0` ❌ |
| `js/sim-bridge.js:155` `canvasEffectiveCount()` | `timeSteps*(subSteps+1)` | 长度算成 **2 倍** ❌ |

绘制按 stride=1 写主值、仿真按 stride=2 采样 → 采样点整体错位一格。
目前被 `sampleMainValue()`（sim-bridge.js:164）的兼容分支 `if (rawValues.length <= timeSteps)`
**短路掩盖**（m_subStepCount=0 时 length 恰好等于 timeSteps，走直取分支，碰巧正确）。
只要子步数 ≥1、或画布步数与 `#sample-spin` 不同步，就立刻错位。
级联后果：`#finish` 时机 `sim.js:589` 的 `timeStep - prevTime` 可能 ≤0 退化成 `#1 $finish` → 仿真立刻结束 → 全 0。
