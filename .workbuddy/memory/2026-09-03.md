### 1. 坐标模型定论（全部写入统一走它）
- 选框端点一律 **globalSampleIndex**（仅由 x 像素决定、全局 divisor 的子步空间下标），
  核心 drawRangeSelection 亦按全局 stride 绘制 → 视觉范围==写入范围。
- 行内可写下标统一经 **wpf.cellsInRange(sig, lo, hi)**（main-step float 中转 + 夹取），
  selection.js 整步/子步/反向拖动全由它产出。
- shortcuts.js / value-input.js 收口：**wpf.divisorOf(sig)** 取代全局 stride()，
  私有 subSteps 行（如 ebit divisor=4）不再框错格。

### 2. 值模型：彻底去位宽

  （width 恒 1 → 多 bit 输入 'A' 写 0 的根因）。
- 全链路唯一解析入口 **wpf.parseValue(raw, sig)**；refreshBusLabels 无 width 幽灵判定。

### 3. 稳定性根治（selection.js 全量重写）
- 根因：工具条聚焦时画布 mousedown → detachBar removeChild → 触发同步 blur → 二次
  removeChild → NotFoundError → 后续选框全 no-op。
- 解法：`detachBar` 先置 `barEl.__closing=true` 并置全局 bar=null → removeChild；
  blur 处理器检查**闭包元素** barEl.__closing 立即 return（不能查全局 bar——可能已 null）。
- 事件走 document capture 层拦截接管，核心原生 mousedown 不会残留脏状态。
