# 功能需求书：总线/位信号「复选编辑」与整步子步粒度约束

> 读者：下一位负责 WavePaintSim 的实现 AI。
> 目的：把「总线复选编辑 + 复刻到单比特 + 粒度约束」这组需求定义清楚，让你无需追问即可开工。

> 对应规划：`docs/任务交接计划_给下一位AI.md` §7.1/7.7/7.8 的**最终需求定义**。

## 0. 需求来源（用户原话，逐条对应）

> 1. 「现在总线选择编辑模式的话，是有多选的功能的，此处代码不知道在哪里，可能是混淆过的，请详细研究，找出正确代码」
> 2. 「这段复选的代码可以直接应用到单比特信号，我是要这个功能再重复一遍，就是将现在现有的对多比特信号复选的功能迁移复刻到单比特信号上」
> 3. 「这个多比特信号原本就有的……选择的这个力度……并不受顶部功能栏整步子步开关的约束」
> 4. 「我希望软件自带的对于总线类型信号复选的这个功能，也受到整步子步功能的约束」

**解读（实现者以此为准）**：
- 「总线复选」= **软件自带的、对 Vector（总线）信号进行"选择→输入值"编辑的功能**（核心原生，见 §1.1）。
- 需求 A：把该「复选编辑」能力**复刻到单比特（Bit）信号**——Bit 也能"选择一段 → 输入值（1/0/x/z）"。
- 需求 B：总线复选编辑的写入**必须遵循顶部「整步/子步」开关**（现状不遵循，见 §1.2）。

## 1. 现状（已实测确认，实现者不必重查）

### 1.1 核心原生「总线编辑」= Vector Value 弹窗（混淆核心，勿改源码）

- **触发**：在**画笔/编辑工具**（`tool-paint`，`data-tool="paint"`）下，**点击 Vector 信号波形格**（不拖动）。
- **表现**：弹出核心原生模态框 **"Vector Value"**，提示 "Enter vector value or label:"，含输入框 + 取消/确定。
- **写入**：确定后把输入值写入**点击的那一个下标**（`mapCanvasPosition` 返回的 `signalSampleIndex`）。
  - 实测：点击 `signalSampleIndex=5`（`mainStep=2`、`subStep=1`、stride=2），写入只改 `values[5]`，相邻 `values[4]`（同一主步的另一子格）**不变** → 说明核心弹窗是**单格写入**。
- **粒度**：**不受**顶部「整步/子步」开关约束（无论开关状态，都是单格写入）。
- **Bit 信号没有对应弹窗**：Bit 在画笔工具下点击/拖动是直接画 0/1（TimeGen 上下半区绘制，`feature-draw.js` 接管）。

### 1.2 feature-select.js 的「框选」（我们写的增强，非核心）

- 选择工具（`tool-select`）下拖动 → 蓝色虚线框选（跨多信号×多格子）→ 浮动工具条（设1/设0/设x/翻转/复制/粘贴/**输入值**/取消）。
- 「输入值」：对 Vector 写任意值（`10/0xA/0b1010/8'hA5/x/z`），对 Bit 写 `1/0/x`。
- 写入是**逐下标**（`for i in sampleStart..sampleEnd: values[i]=...`），**不受**整步/子步开关约束（同 §1.1 问题）。
- **⚠ 已知问题**：当前 exe 内嵌的是**旧版** `feature-select.js`（**没有输入框和"输入值"按钮**，只有 7 个批量按钮）。磁盘上的新版代码有输入框，但**未重建 exe**。实现本需求时必须重建 exe，否则用户看不到输入值入口。

### 1.3 核心相关机制（已定位，供参考）

| 机制 | 说明 |
|---|---|
| `wpPrompt(message, defaultValue, title)` | 核心通用输入弹窗（`openWpModal` 封装），返回 `Promise<{ok, value}>` |
| `SignalType.Bit=0 / Vector=1` | 信号类型（核心全局） |
| `drawVectorSelectionHighlight` / `drawMultiSelectionHighlight` | Vector/多选高亮绘制函数（画布渲染时调用） |
| `selectedSignalIndices` | 核心多信号选择数组（Ctrl/C/V、Delete 多信号操作），与波形段选择无关 |
| 全局 `Selection` 对象 | 死代码（定义+isInSelection+clearSelection，无赋值点），不要依赖 |

## 3. 详细需求

### R1 — Bit 信号获得「总线式」值输入编辑 【P0】

**用户故事**：我编辑位信号时，也想像总线那样"点一下或框选一段，输入 `1`/`0`/`x`/`z`（或一段位串如 `1010`）就写入"，而不是只能靠画笔一格一格画。

**交互流程（与 Vector Value 弹窗对齐）**：

1. **画笔/编辑工具下点击 Bit 信号格**（不拖动）：
   - 弹出**值输入弹窗**（复用核心 `wpPrompt` 或 `feature-common` 自建弹窗，标题如 "Bit Value"，提示 "Enter bit value (1/0/x/z)："，默认值为当前格的值）。
   - 输入 `1/0/x/z`（也接受 `u/d`）→ 确定 → 按 R2 粒度写入。
   - 输入多位（如 `1010`）→ 从点击格开始逐格写入，超出截断、不足**循环重复**（`101`→`10110`）。
2. **画笔/编辑工具下拖动 Bit 信号**：
   - 普通拖动 = TimeGen 连续绘制（**保持现状，不得破坏**）。
   - **修饰键（推荐 Ctrl）+ 拖动 = 框选**一段 → 松开弹出输入弹窗 → 输入值写入整段。
3. **选择工具下框选 Bit**（现状已有）：工具条保留设1/设0/设x/翻转/复制/粘贴，**补上「输入值」输入框**（磁盘版已有，重建 exe 即可见），并让 Bit 的「输入值」接受 `1/0/x/z` 与位串（现状已支持，补粒度 R2）。

**边界规则**：
- 单击 Bit 弹窗时，若当前处于**整步**模式 → 写入该主步全部 `stride` 格；**子步**模式 → 只写点击的子格（由 R2 统一处理）。
- 输入非法字符（非 1/0/x/z/u/d）→ 弹窗内红框提示（R8），不写入、不关闭。
- 空选择（框选完全在波形区外）→ 不弹窗，状态栏提示（R8）。

---

### R2 — 总线复选编辑受「整步/子步」开关约束 【P0，用户点名的「力度」】

**目标**：所有"选择一段 → 输入值"的写入路径，写入粒度**跟随顶部「整步/子步」开关**（`wpf.editGranularity()`）。

**必须覆盖的写入路径**：

| # | 路径 | 现状 | 要求 |
|---|---|---|---|
| ① | **核心 Vector Value 弹窗**（画笔下点击 Vector 格） | 单格写入，无视开关 | **整步**：写该主步全部 `stride` 格（`values[mainStep*stride..+stride-1]` 全变）；**子步**：只写点击的子格。**通过 feature 模块接管实现**（核心不可改：捕获画笔下点击 Vector 的事件，拦截核心弹窗，自行弹窗并按粒度写入） |
| ② | **feature-select 框选「输入值」**（Vector 与 Bit） | 逐下标写入，无视开关 | 整步：每个被覆盖主步写全部 `stride` 格；子步：只写覆盖的格子 |
| ③ | **R1 新增的 Bit 值输入** | — | 同上 |

**★ 实现捷径（务必利用）**：`wpf.writeValue(sig, sampleIndex, value)`（`feature-common.js`）**内部已按当前粒度处理**——`'step'` 时铺满主步全部 `stride` 格并清 `clockMarkers`，`'substep'` 时只写该下标。因此所有路径只需对每个目标下标调用 `wpf.writeValue(sig, i, value)` 即可，无需自判粒度。

**粒度取值**：`wpf.editGranularity()` 返回 **`'step'`**（整步，默认）或 **`'substep'`**（子步）——注意**不是** `'mainstep'`。

**数据一致性**：写整步时，Vector 需 `wpf.refreshBusLabels(sig)` 重算标签；`clockMarkers` 由 `writeValue` 自动清理；`syncSignalMeta` 仅在长度变化时需要。

---

### R3 — 交互形态统一 【P0】

- **输入弹窗**（单击触发）：复用核心 `wpPrompt`（`window` 上未必暴露，若未暴露则用 `feature-common.js` 自建一个等价的轻量弹窗，样式与 `#wp-modal` 一致），标题区分 "Vector Value"（总线，保留核心原样）/ "Bit Value"（位信号，新增）。
- **浮动工具条输入框**（框选触发）：沿用 `feature-select.js` 现有输入框（磁盘版已有），统一用 `normalizeVectorValue`（Vector）与新增的 `normalizeBitValue`（Bit）解析。
- 输入框**自动聚焦**；`Enter` 确认、`Escape` 取消；工具条/弹窗内按键不得触发全局快捷键（`stopPropagation`）。
- 弹窗/工具条标题或副标题显示当前粒度（如 "整步" / "子步" 灰色小字）。

---

### R4 — 撤销 【P0】

- 每次输入值写入（弹窗确定 / 工具条确定 / Bit 框选输入）**在写入前**调一次 `wpf.pushUndoSnapshot()`。
- Ctrl+Z 整体回退该次写入；Ctrl+Y 重做。
- **验收**：写入后 Ctrl+Z → 波形完整回到写入前；再 Ctrl+Y → 恢复。

---

### R5 — 与现有功能互不冲突 【P0】

| 现有功能 | 冲突点 | 解决 |
|---|---|---|
| TimeGen 绘制（`feature-draw.js`，画笔下 Bit 拖动=画） | R1 的 Bit 框选与绘制共用"拖动" | 普通拖动=绘制；**修饰键（推荐 Ctrl）+拖动=框选**；单击=弹窗（与绘制不冲突，绘制需 mousedown+move） |
| 核心 Vector Value 弹窗（画笔下 Vector 点击） | R2 ① 要接管 | feature 模块在 document 捕获阶段拦截画笔下 Vector 的 `mousedown`/`click`，`stopImmediatePropagation` 阻止核心弹窗，自弹自写 |
| 选择工具框选（`feature-select.js`） | 两套框选并存 | 提取公共组件（R3），行为保留，仅补「输入值」与粒度 |
| 快捷键（`feature-shortcuts.js`） | 输入框/弹窗内按键误触发 | 输入元素 keydown 一律 `stopPropagation` |
| 原版单击选中/属性面板 | 单击 Bit/Vector 弹输入框与"选中"冲突 | 仅**单击波形格**弹输入框；点信号名/空白放行原版（`clickedOnName` 判断） |
| 监听器注册顺序 | 多模块捕获监听互相影响 | `index.html` 顺序：feature-common → feature-marquee(若新建) → feature-select → feature-value-edit(R1/R2 新模块) → feature-draw；同一事件互斥短路（接管后 `stopImmediatePropagation`，其它模块识别并 return） |

---

### R6 — 输入时实时预览 【P1】

- 输入框内容合法时，目标范围（点击格或框选区）以**半透明预览色**绘制新值波形；回车确认后实写。
- 非法输入显示红框（R8）。
- 实现：`input` 事件 → 解析 → 合法则在 overlay 上绘制预览（可复用 `feature-select.js` 的 overlay 组件）。

---

### R7 — 总线进制联动 【P1】

- Vector 输入支持 `10 / 0xA / 0b1010 / 8'hA5 / x / z`；写入后标签按**信号当前 radix** 显示（`wpf.busRadixLabel` 已实现）。
- **验收**：radix=hex，输入 `165` → 显示 `A5`；radix=bin，输入 `0xA5` → 显示 `10100101`。

---

### R8 — 非法输入/空选择提示 【P2】

- 非法输入 → 输入框红框 + tooltip（Vector: "仅支持 10/0xA/0b1010/8'hA5/x/z"；Bit: "仅支持 1/0/x/z"）。
- 空选择（`regionFromPoints` 返回 null）→ 不弹窗，在 `#sim-status` 或画布上方提示「未选中有效波形区域」。
- 验收：均可见反馈，无静默、无控制台异常。

## 4. 技术实现建议

### 4.1 模块结构

```
js/
├─ feature-common.js        # 已有：wpf.writeValue / pushUndoSnapshot / refreshBusLabels /
│                           #       busRadixLabel / editGranularity / stride / mapAt
├─ feature-marquee.js       # 【可选新建】公共框选组件（虚线框 + 工具条 + 输入框），
│                           #       供选择工具与画笔下的 Ctrl+拖动共用
├─ feature-select.js        # 改造：接入公共组件；补「输入值」粒度（R2②）；行为不变
├─ feature-value-edit.js    # 【新增核心模块】R1+R2①：
│                           #   1) 接管画笔下点击 Vector → 拦截核心弹窗 → 自弹窗按粒度写入
│                           #   2) 画笔下点击 Bit → 弹 Bit Value 弹窗按粒度写入
│                           #   3) 画笔下 Ctrl+拖动(Bit/Vector) → 框选 → 输入值按粒度写入
└─ feature-draw.js          # 微调：识别 Ctrl+拖动 → return 让位给 feature-value-edit；
                            #      普通拖动保持 TimeGen 绘制
```

### 4.2 已可用资产（直接用，别重造）

| API | 位置 | 用途 |
|---|---|---|
| `wpf.mapAt(clientX, clientY)` | feature-common | 命中测试 → `{signalIndex, signalSampleIndex, clickedOnName, mainStep, signalSubStep}` |
| `wpf.writeValue(sig, sampleIndex, value)` | feature-common | **★ 统一写入入口，内部按粒度处理整步/子步 + 清 clockMarkers** |
| `wpf.editGranularity()` / `setEditGranularity()` | feature-common | 粒度，返回 `'step'`/`'substep'` |
| `wpf.pushUndoSnapshot()` | feature-common | 撤销快照（委托核心，100 上限） |
| `wpf.refreshBusLabels(sig)` / `wpf.busRadixLabel(v,w)` | feature-common | 总线标签重算 |
| `window.__wpfVec.normalizeVectorValue(raw, w)` | model.js | Vector 输入解析 |
| `wpPrompt(msg, def, title)` | 混淆核心（若未暴露到 window 则自建） | 输入弹窗 |
| `window.SignalType.Bit/.Vector` | 混淆核心 | 信号类型 |

### 4.3 写入核心伪代码（R1+R2 统一）

```js
function applyValue(sig, targetIndices /* 数组 */, rawValue) {
  wpf.pushUndoSnapshot();
  const isVec = sig.type === window.SignalType.Vector;
  const value = isVec
    ? window.__wpfVec.normalizeVectorValue(rawValue, vectorWidth(sig))
    : normalizeBitValue(rawValue);              // '1'|'0'|'x'|'z'|'u'|'d' 或位串
  if (value === null) { showInvalid(rawValue); return; }   // R8
  for (const i of targetIndices) {
    wpf.writeValue(sig, i, value);              // ★ 粒度由 writeValue 内部处理
  }
  if (isVec) wpf.refreshBusLabels(sig);
  wpf.scheduleRedraw();
}
```
