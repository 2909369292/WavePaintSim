# 补丁与妥协清单（重构对象）

> 起因：混淆核心不暴露内部 API，历次迭代被迫在**外部**用 DOM/事件 hack 达成目标。
> 解混淆后（`wavepaint.clean.js`）已证明：全部业务在顶层作用域，323 个 function +
> 核心状态（`currentTool/isMouseDown/rangeSelActive/rangeSelecting/rangeSel*Sample` 等）
> 均可直接访问 —— 以下补丁**全部可以改为核心内官方实现或干净调用**。
> 清理顺序按「依赖最底层优先」，每清理一步回归一次。

---

## A 类：核心内部能力外泄型 hack（最该清）

### A1. 合成事件驱动核心原生框选  ← 最大最脏
- 文件：`feature-select.js` 主体 + `feature-common.js` 少量
- 现状：为了「按整步/子步粒度框选 + 复用原生视觉」，把真实鼠标坐标按粒度对齐后
  **伪造 `mousedown/mousemove/mouseup` 合成事件**派发给核心（`dispatchAt` /
  `dispatchRaw` / `xForSample` 二分求坐标 / `replaying` 防递归 / `clearCoreSelection`
  用同点 down+up 清选框 / 方向感知 `dirChanged` 重派 mousedown / 对 Vector 不派发
  mouseup 防核心弹窗 / 子步单格不派发 up 防「无拖动清除」…）
- 痛点：与核心事件系统强耦合、时序脆弱（前几轮大量 bug 都源于此）、代码难读
- **去 hack**：核心状态全在顶层（`rangeSelStartSignal/Sample/EndSignal/EndSample/
  rangeSelActive/rangeSelecting`），直接置状态 + `drawWaveform()` 即可画/清选框。
  把「粒度对齐」作为核心画布模型内置语义（见 C1），合成事件层整体删除。

### A2. MutationObserver 抑制核心自带弹窗
- 文件：`feature-common.js`（ready 块）、`feature-value-edit.js`（`wpf._promptActive`）
- 现状：核心在 select 工具下对 Vector 完成框选会弹自带「Vector Value」(`wpPrompt`)
  并把工具切回画笔；扩展想要自己的输入流，故用 MutationObserver 观察
  `#wp-modal-overlay`，见到核心显示就立刻隐藏并抵消工具切换
- 痛点：竞态（`_promptActive` 残留曾放行弹窗 → 遮罩挡住全部操作）
- **去 hack**：直接在核心内 `wpPrompt` 相关调用点按信号类型/上下文决定弹不弹、
  弹哪个（统一入口交给扩展注册的 handler），MutationObserver 删除。

### A3. 原型补丁 patchCoreValueToLabel
- 文件：`feature-common.js`（`patchCoreValueToLabel` + `wpf.__origCoreValueToLabel`）
- 现状：核心 `valueToLabel` 对总线位串显示不合需求（前缀/位宽/-1 处理），运行时
  **替换原型方法**，保留原引用兜底防递归
- 痛点：原型替换脆弱；补丁版与核心自绘路径叠加易混乱
- **去 hack**：在核心内部直接改写 `valueToLabel`/`formatVectorValue`/位宽换算实现，
  补丁函数删除。

### A4. 总线进制刷新入口外挂
- 文件：`feature-common.js`（`applyBusRadix/refreshBusLabels/setSignalRadix` 等）
- 现状：核心改进制后不重绘总线标签；扩展扫描画布信号逐个刷
- **去 hack**：改核心的进制变更函数内嵌标签刷新；外部只保留「设置」语义，去掉扫描兜底。

### A5. 中文汉化走 DOM 层
- 文件：`zh-lang-patch.js`
- 现状：核心 `wpPrompt` 等动态英文在弹窗前经 DOM 拦截翻译
- **去 hack**：直接改核心内文案（字符串已还原，可直接编辑）或给 `wpPrompt` 挂
  翻译回调；DOM 拦截删除。

### A6. 输入防抖节流
- 文件：`step-commit-patch.js`
- 现状：核心对步数/子步输入框每次 key 都全量重渲染导致闪烁；补丁改为 blur/Enter 提交
- **去 hack**：改核心输入事件绑定，天然节流。
- ✅ 已关闭（2026-09-02）：`clean.js` 两处 spin 的 `addEventListener('input')` → `('change')`，
  `js/patch/step-commit.js` 删除、`js/patch/` 目录清零；resize.js 捕获阶段仍先于核心收到
  change 并执行智能 resize（e2e-ui D 节验证：input 中间态不生效、change 提交）。

## B 类：与核心数据模型摩擦的适配（保留但重写为数据层）

### B1. Bit 值编码换算
- `sim-bridge.js`：`toNativeBitValue/fromNativeBitValue`；`model.js` 部分
- 原由：画布 values 用数字 0/1/-1/2/3/4，仿真文本用 '0'/'1'/'x'…
- 重构：归入统一「波形编码层」（见 C1），双向转换单一实现，供编辑/仿真共用。

### B2. 画布→TB 的布局换算
- `sim-bridge.js`：`canvasTimeSteps/canvasEffectiveCount/readWaveDocument/sampleMainValue`
- 原由：values 线性布局 = 主步×stride，仿真需要主步粒度采样 + 时钟逐格序列
- 重构：归入 C1 数据模型 API（读主步值/写主步值/子步访问），口径单一、注释清晰，
  **不再允许外部各自推导 stride 口径**（历史多次因口径不一致翻车）。

### B3. 编辑粒度语义（整步铺满 / 子步单格）
- `feature-common.js`：`writeValue/indicesByGranularity` + `editGranularity` 状态
- 现状：整步粒度下 `writeValue` 把整个主步 stride 格写同值（仿真采样才正确）；
  子步粒度只写单格。已稳定，但实现藏在 feature-common
- 重构：提升为 C1 数据模型的正式写操作 `wave.setCell(sig, sample, value)`，
  粒度作为写策略参数；同步维护 `clockMarkers`。

## C 类：历史修复的正确归宿

| 原文件 | 内容 | 归宿 |
|--------|------|------|
| `utils.js` | 唯一 id 生成（修核心 Math.random 碰撞） | 数据层 util，或直接改核心 |
| `feature-resize.js` | 步数变化时波形伸缩（修核心 resize 丢波形） | 保留为 editor/resize.js |
| `feature-value-edit.js` 弹窗流程 | 复用 `#wp-modal` 做 Bit/Vector 输入 | 归 editor/value-prompt.js，用 __core.prompt |
| `feature-select.js` 工具条 | 设1/0/x/翻转/输入 | 归 editor/selection.js（去掉合成事件） |
| `feature-common.js` 其余 wpf.* | 坐标/行带/粒度/进制/就绪等 | 分拆进 core-api 与 editor 各域 |

## 去 hack 后的核心改动原则
1. `wavepaint.clean.js` 仍是解混淆产物 → **保持可再生成**：对核心的内部修改一律
   追加到文件尾部的「补丁段」或独立 `core.patch.js`（同一顶层作用域可直接访问），
   并在 `tools/deobfuscate.mjs` 里可选把补丁段拼回（重跑不丢）。
2. 对外只暴露**有语义的稳定入口** `window.__core.*`，禁止扩展直接抓内部名字。
3. 每步回归：34 项回归 + 浏览器像素/交互 e2e。
