## 1. 项目环境与构建流程（必须先看）

### 1.1 环境

- 操作系统：Windows（本机 PowerShell 5.1）
- Node.js：可用（用于验证 JS 语法：`node --check 文件名`）
- 构建编译器：`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（.NET Framework 4.0）
  - ⚠ **C# 4.0 语法**：**不支持** `out int x` 内联声明、`var` 之外的 C# 7+ 特性、`??=`、switch 表达式等。必须写 `int port; TryParse(s, out port);`

### 1.2 构建与重启（每次改 JS/C# 后必做）

```powershell
# 1) 杀掉所有实例（单实例保护，直接 build 会因 exe 被占用而失败）
Get-Process WavePaint -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep -Milliseconds 800
# 2) 清理残留（可选，但推荐）
Get-ChildItem $env:TEMP -Filter "WavePaintSim_*" -ErrorAction SilentlyContinue | Remove-Item -Recurse -Force -ErrorAction SilentlyContinue
# 3) 构建（把 index.html + js/ + css/ + img/ + lib/ + ivl.zip 内嵌进 WavePaint.exe）
Set-Location "d:\Files\Code\波形\WavePaintSim"
& .\build.ps1     # 成功标志：csc exit: 0，WavePaint.exe size 约 22MB
# 4) 启动（单实例，自动打开 Edge --app 窗口）
Start-Process -FilePath "d:\Files\Code\波形\WavePaintSim\WavePaint.exe" -WorkingDirectory "d:\Files\Code\波形\WavePaintSim"
Start-Sleep -Seconds 4
# 5) 读取端口（页面地址）
Get-ChildItem $env:TEMP -Filter "WavePaintSim_port_*.txt" | ForEach-Object { "PORT: " + (Get-Content $_.FullName) }
# 页面：http://127.0.0.1:<PORT>/index.html
```

- `build.ps1` 会把以下资源内嵌进 exe：`index.html`(root_)、`css/*`(css_)、`js/*`(js_)、`img/*`(img_)`、`lib/*`(lib_)、`ivl.zip`。
- 运行时 WavePaint.exe 把资源解压到 `%TEMP%\WavePaintSim_<用户名>\`，起 HttpListener（随机端口），用 Edge `--app` 打开。
- **新增 JS 文件必须确保能被 `build.ps1` 打包**（`js\*` 通配，会自动包含），并在 `index.html` 中加 `<script src="...">`。

### 1.3 index.html 脚本加载顺序（关键）


### 2.3 数据模型（关键，务必理解）

```
Signal 字段（实测）：
  name, type(Bit|Vector|BlankRow), width, msb, lsb,
  values[], labels[], segmentStyles[], driveStrengths[],
  clockMarkers[], waveDromColorCodes[], edgeArrow,
  color, fill, riseTime, fallTime, subSteps, isClockPattern,
  clockHighSamples, clockLowSamples, showClockMarkers, uiRowHeightHint,
  groupName, groupColor, groupPath, radix

位值编码（Bit 信号 values 是数字数组）：
  0=低, 1=高, -1=未定义(x), 2=高阻(z), 3=上拉(u), 4=下拉(d)
  Vector 信号 values 是字符串数组（如 "0000" / "xxxx" / "f"）

⚠⚠⚠ 核心规则：values.length = m_sampleCount × (m_subStepCount + 1)
  实测：
    步数30 / 子步1 → 长度 60
    步数30 / 子步2 → 长度 90
    步数50 / 子步1（由30改来）→ 长度 100（原版自动 resize）
    步数20 / 子步1（由50改来）→ 长度 40

  即：每个时间步占 (子步数+1) 个 values 下标（子步内部 + 步边界）。
  "主值"约定：每个时间步的第 1 个值（下标 = 步号 × (子步+1)）作为该步的值。
```

### 2.4 画布坐标映射（mapCanvasPosition 实测返回）

```js
window.mapCanvasPosition(clientX相对canvas, clientY相对canvas)
// 返回对象字段：
{
  signalIndex,            // 命中第几个信号；-1 = 未命中信号带（点到了名称区/空白）
  signal,                 // 命中的 Signal 对象（未命中为 null）
  clickedOnName,          // 是否点在信号名称区
  position,               // 主步位置（浮点）
  mainStep,               // 主步号（0 起）
  subStepFraction,
  globalSampleIndex, globalSubStep, globalSubSteps, globalDivisor,
  globalEffectiveCount,   // = m_sampleCount × (m_subStepCount+1)
  signalSampleIndex,      // ★ 直接对应 values 数组下标（写值就写这里）
  signalSubStep, signalSubSteps, signalDivisor, signalEffectiveCount,
  nameWidth,              // 名称区宽度（约 80px）
  relX, stepWidth,        // 每主步宽度（px）
  globalStepWidth, signalStepWidth  // 每个子步宽度（px）
}
```

**信号带 y 位置探测**：信号带在画布顶部附近（实测 y≈0.1×canvas高度 命中第 0 个信号；canvas 高约 609px）。实施时用 `mapCanvasPosition(x, y)` 循环探测，找到 `signalIndex >= 0` 的 y 区间即为信号带。

### 2.5 原版交互行为（现状）

- 绘制：在 `#wave-canvas` 上 `mousedown`/`mouseup` 点击写入当前位状态（位状态由工具栏选择器 `#tool-bit-state` 决定，默认值 1/0/z/x/u/d）。
- 步数修改：`#sample-spin` change → 原版把每个信号 values resize 成 `新步数×(子步+1)`（保留前部已有值，尾部补"空/未定义"）。
- 子步修改：`#substep-spin` change → 同理 resize。
- `step-commit-patch.js` 已实现：输入过程中不逐键重绘，blur/Enter 时提交。

### F1 P0：添加信号长度对齐数据模型（最优先）

**需求背景**：用户反馈"添加的波形长度不对、波形格式不严谨"。根因是：`sim-bridge.js` 的「添加信号」按钮（`#sim-addsignals`）创建的信号 `values.length = 步数`，而 WavePaint 原版模型要求 `values.length = 步数 × (子步+1)`。两者不一致导致：改步数后原版 resize 行为异常、绘制/导出/仿真采样错位。

**现状代码**（`js/sim-bridge.js`）：

- `canvasTimeSteps()`（约 128-143 行）：返回主步数（读 `#sample-spin`）。
- `toNativeSignal(output, index, template, timeSteps, options)`（约 165 行起）：内部 `new SignalCtor(name, normalizeSignalType(width), timeSteps)` 以 `timeSteps`（主步数）创建，随后 `base.values = values`（长度 = timeSteps）。
- `addPortSignalsToCanvas()`（约 474 行起）：`const timeSteps = canvasTimeSteps();` 传给 `toNativeSignal`。
- `readWaveDocument()`（约 293 行起）：读画布信号构造 project，`timeSteps = canvasTimeSteps()`，`values` 数组长度 = timeSteps，**直接从 rawValues[cell] 取值（当前 cell 下标直接当主步用，未按 ×(子步+1) 采样）**。

**目标行为**：
1. 「添加信号」创建的激励信号 `values.length = 主步数 × (子步数+1)`，全部填"未定义 x"（Bit=-1，Vector="xxx…"）。
2. `readWaveDocument()` 按数据模型采样：每个主步取**该步第 1 个值**（下标 = 步号 × (子步+1)）作为仿真激励值。
3. 仿真输出信号（`replaceInjectedOutputs` 注入的）长度同样为 `主步数 × (子步+1)`。

**实现步骤**：

1. 在 `sim-bridge.js` 新增：
   ```js
   // 画布有效采样数 = 主步数 × (子步+1)，与 WavePaint 数据模型一致
   function canvasEffectiveCount() {
     const steps = canvasTimeSteps();
     const dw = window.document_wave;
     const subs = Math.max(1, Number(dw?.m_subStepCount || 1) || 1);
     return steps * (subs + 1);
   }
   ```

2. 修改 `addPortSignalsToCanvas()`：把 `const timeSteps = canvasTimeSteps();` 改为
   ```js
   const timeSteps = canvasTimeSteps();        // 主步数（仍用于 createSignalFromPort）
   const effectiveCount = canvasEffectiveCount(); // 画布 values 长度
   ```
   并把 `toNativeSignal(signal, baseCount + added, template, timeSteps, {...})` 的第 4 参改为 `effectiveCount`。
   ⚠ 注意：`createSignalFromPort(port, null, "stimulus", timeSteps)` 仍用主步数生成 project 模型值（全 x，长度=主步数即可，因为 readWaveDocument 会按模型重新采样——见下一步）。如果实现上有冲突，可让 `createSignalFromPort` 也生成 `effectiveCount` 长度，再在 `toNativeSignal` 里直接铺开。

3. 修改 `readWaveDocument()`：`const timeSteps = canvasTimeSteps();` 处新增子步读取，并**按模型采样**：
   ```js
   const subSteps = Math.max(1, Number(dw?.m_subStepCount || 1) || 1);
   const stride = subSteps + 1;               // 每主步占 values 下标数
   const timeSteps = canvasTimeSteps();       // 主步数（project.timeSteps 语义不变）
   ```
   信号映射处，`values` 生成改为：
   ```js
   const values = Array.from({ length: timeSteps }, (_, cell) => {
     const raw = rawValues[cell * stride];    // 每主步取第 1 个值（主值）
     return width <= 1 ? fromNativeBitValue(raw) : normalizeVectorValue(raw, width);
   });
   ```
   （原代码是 `rawValues[cell]`，改成 `rawValues[cell * stride]`。）

4. 修改 `replaceInjectedOutputs()`（约 220-233 行）：其内部 `timeSteps` 计算改为 `canvasEffectiveCount()`，让仿真输出信号长度也对齐：
   ```js
   const timeSteps = canvasEffectiveCount();
   ```

5. 若 `toNativeSignal` 中 `new SignalCtor(name, type, timeSteps)` 第三个参数对 Vector 长度有额外影响，请以实际运行结果为准（目标：Bit 信号 values 长度 = effectiveCount，Vector 同）。

**验收标准**：
- 步数 30、子步 1 时点「添加信号」→ 信号 `values.length === 60`，全为 `-1`（x）。
- 步数 30、子步 2 时 → 长度 `90`。
- 修改步数后（原版 resize）→ 长度始终 = 当前步数 × (子步+1)，且第 1 个值（主值）与改前对应。
- 点「Sim」仿真结果与手动画波形一致（时钟在画布上升沿采到主值）。
- 验收方法见第 5 节（用浏览器 DevTools 或 Playwright 检查 `document_wave.m_signals[i].values.length`）。

### F2 P1：TimeGen 式鼠标绘制（上移画1/下移画0）（用户点名）

**需求背景**（用户原话）："现在01绘制的功能比较麻烦，我希望可以鼠标点击鼠标上移，就是说偏上面靠的时候绘出来的是1，鼠标偏下面靠的时候绘出来是零，就是类似于 timeGen 这个软件类似的效果。"

**现状**：在 `#wave-canvas` 上点击，写的是**当前位状态选择器选中的值**（默认 1）。必须先在工具栏选 0 或 1，才能画对应值。

**目标行为**：
1. 默认模式（称"自动 0/1 模式"）：鼠标在**信号带内**按下/拖动时：
   - 指针位于**信号带竖直方向的上半区** → 写 **1**
   - 指针位于**信号带竖直方向的下半区** → 写 **0**
   - 松开后保持（非实时预览也行，但推荐按住拖动实时画）。
2. **按住左键拖动**可连续绘制（跨格子写 0/1）。
3. 若用户通过位状态选择器选中了 x/z/u/d（非 0/1 的固定值），则退化为"固定值模式"（点击写所选值，不按上下区分）。
4. 原有"选择工具 / 橡皮擦 / 箭头"等其它工具行为不受影响（只有画笔类绘制模式启用该交互）。
5. 键盘组合（可选）：按住 `Shift` 拖动 = 擦除（写 x）或写 0（二选一，建议 Shift=擦除写 x）。

**实现步骤**（新增 `js/feature-draw.js`）：

1. 在 `#wave-canvas` 上用**捕获阶段**监听 `mousedown`/`mousemove`/`mouseup`，`stopImmediatePropagation()` 拦截原版（确保我们优先）。
   - 参照 `step-commit-patch.js` 的捕获写法。
2. 判定"是否启用自动 0/1 模式"：
   ```js
   function getCurrentBitState() {
     // 读取工具栏位状态选择器当前选中的 data-state（1/0/z/x/u/d）
     const active = document.querySelector('.bit-state-option.active, #bit-state-picker [data-state].active');
     return active ? active.getAttribute('data-state') : '1';
   }
   function isAutoMode() {
     const st = getCurrentBitState();
     return st === '1' || st === '0'; // 选择器当前是 0/1 时启用自动模式
   }
   ```
   （若选择器结构不同，以实际 DOM 为准：位状态菜单项带 `data-state="1|0|z|x|u|d"`。）
3. `mousedown` 处理：
   ```js
   function onPointerDown(e) {
     if (!isAutoMode() || e.button !== 0) { /* 放行给原版或按原逻辑 */ return; }
     e.stopImmediatePropagation();
     dragging = true;
     paintAt(e);
   }
   ```
   `paintAt(e)`：
   ```js
   function paintAt(e) {
     const canvas = document.getElementById('wave-canvas');
     const rect = canvas.getBoundingClientRect();
     const m = window.mapCanvasPosition(e.clientX - rect.left, e.clientY - rect.top);
     if (!m || m.signalIndex < 0 || m.signalSampleIndex < 0) return;
     const sig = window.document_wave.m_signals[m.signalIndex];
     if (!sig || sig.type === window.SignalType.BlankRow) return;

     const inBandY = /* 计算 y 相对该信号行顶部的偏移 */;
     const half = /* 该信号行高的一半 */;
     const value = inBandY < half ? 1 : 0;   // 上半=1，下半=0
     sig.values[m.signalSampleIndex] = value;
     scheduleRedraw();
   }
   ```
   - **信号带 y 探测**：在浏览器里用 `mapCanvasPosition` 扫 y（0~canvas.height），记录命中每个 `signalIndex` 的 y 区间。若 `mapCanvasPosition` 不提供行内偏移，可读取 `m.signal` 对应的行高（`uiRowHeightHint` 或 canvas 高度/信号数）。**务必实测确认**，因为信号带可能在顶部且高度很小（实测 y≈0.1×高命中信号 0）。
   - 若拿不到精确行内 y，退而求其次：**用整个信号行高度的一半**判定（即点击信号行的上半=1、下半=0）。
4. `mousemove`（拖动）处理：`if (dragging) paintAt(e);`（可加节流，如 requestAnimationFrame）。
5. `mouseup`/`mouseleave`：`dragging = false;`。
6. 重绘节流：
   ```js
   let raf = 0;
   function scheduleRedraw() {
     if (raf) return;
     raf = requestAnimationFrame(() => { raf = 0; window.drawWaveform?.(); window.updateSidePanels?.(); });
   }
   ```
7. **保存原版处理**：若不想完全接管（比如还需要原版的选择/橡皮擦），可仅在"自动模式"下接管，其它模式放行（不调用 stopImmediatePropagation）。

**边界情况**：
- 点在信号名称区（`m.clickedOnName === true`）→ 不绘制。
- 点击 BlankRow（空白行）→ 不绘制。
- 拖动跨越多个信号行 → 应切换到目标信号（用 `m.signalIndex`）。
- 用户用橡皮擦工具时 → 不启用自动模式（橡皮擦有自己工具状态，需判断当前工具）。

**验收标准**：
- 默认状态下，在信号带上半点击 → 该格变 1；下半点击 → 变 0。
- 按住拖动划过多个格子 → 连续写 0 或 1（依 y 位置）。
- 切到位状态 x 后点击 → 写 x（固定值模式生效）。
- 原版选择工具、橡皮擦、缩放等功能不失效。

### F3 P1：步数/子步变化自适应（用户点名）

**需求背景**：用户希望"调节画布宽度也就是步数的时候，现有的波形可以随步数的变化而自动的填补和修改"。现状：原版 resize 只保留前部、尾部补"未定义"，不够智能。

**目标行为**：
1. **增大步数**（如 30→50）：
   - **时钟类信号**（`isClockPattern === true` 或 kind=clock）：按已画周期**自动延续**（如 `0101…` 继续 `0101…`）。
   - **其它信号**：延续最后一个确定值（若最后是 0 继续 0，是 1 继续 1）；若整行是 x 则补 x。
   - （可选增强）复位信号（名字含 rst/reset）：延续最后值即可。
2. **减小步数**：截断到新长度（保留前部）。
3. **子步数变化**（1↔2）同理：新长度 = 步数 × (子步+1)，主值按每步第 1 个值保留，新增的子步值填主值。
4. 上述行为**可撤销**（最好进撤销栈；若无法接入原版撤销栈，至少保证是确定性的，并在文档/状态栏提示）。

**实现步骤**（新增 `js/feature-resize.js`）：

1. 捕获 `#sample-spin` 和 `#substep-spin` 的 `change` 事件（捕获阶段 + `stopImmediatePropagation`），拦截原版 resize。
2. 自己实现 resize：
   ```js
   function resizeSignals(newSteps, newSubs) {
     const dw = window.document_wave;
     const stride = newSubs + 1;
     const newLen = newSteps * stride;
     for (const sig of dw.m_signals) {
       const old = sig.values || [];
       const next = new Array(newLen);
       for (let i = 0; i < newLen; i++) {
         const oldIdx = i;                       // 若子步数没变，按下标直接对应
         if (i < old.length) { next[i] = old[i]; continue; }
         // 超出部分：智能延续
         next[i] = extendValue(sig, old, i);
       }
       sig.values = next;
       // labels / segmentStyles / driveStrengths / clockMarkers / waveDromColorCodes 长度同步
       sig.labels = syncArr(sig.labels, newLen, '');
       sig.segmentStyles = syncArr(sig.segmentStyles, newLen, null);
       sig.driveStrengths = syncArr(sig.driveStrengths, newLen, 0);
       sig.clockMarkers = syncArr(sig.clockMarkers, newLen, false);
       sig.waveDromColorCodes = syncArr(sig.waveDromColorCodes, newLen, null);
     }
     dw.m_sampleCount = newSteps;
     dw.m_subStepCount = newSubs;
     window.drawWaveform?.();
     window.updateSidePanels?.();
   }
   ```
   - **时钟延续** `extendValue(sig, old, i)`：若 `sig.isClockPattern`，从 old 中解析周期（如每 2 个下标一组 `0,1`），按周期外推 `i` 处的值；否则返回最后确定值（`old` 中最后一个非 `-1` 的值）。
   - 若子步数变化导致下标映射变化，需按"主步 × (子步+1)"重排而不是直接下标对应——**实施时重点处理**：建议先按主步提取旧主值序列，再按新 stride 重建。
3. 若想进撤销栈：查看原版是否有全局 `window.addToUndoStack` 之类（混淆不可见），可用 `document.execCommand` 或调用原版保存快照函数；**若无法接入，跳过撤销栈**（非必须）。

**验收标准**：
- 画一个 `0101…` 时钟（30 步），改步数为 50 → 波形延续成 `01010101…`（长度 100）。
- 画 `0` 保持，改步数 50 → 尾部延续 0（长度 100）。
- 改回 30 → 截断回原样。
- 子步 1→2：长度 60→90，主值不变，新增子步值=主值。

### F4 P2：键盘快捷键绘制

**需求背景**：提高绘制效率。

**目标行为**（新增 `js/feature-shortcuts.js`）：

**实现步骤**：

**验收标准**：在画布区域按 1/0/X/Z 能切换位状态；Ctrl+Z 能撤销。

## 6. 常见坑与注意事项

1. **csc 是 C# 4.0**：改 `WavePaintLauncher.cs` 时禁止 C# 7+ 语法（`out int x`、`??=`、switch 表达式）。必须 `int x; TryParse(s, out x);`。
2. **改 JS 后必须重建 exe**：`build.ps1` 内嵌资源，直接刷新页面不会加载新 JS（除非你是用源文件起的 HttpServer）。构建前先杀 WavePaint 进程（exe 被占用会报 CS0016）。
3. **单实例**：`WavePaintLauncher.cs` 有 Mutex 单实例保护（`Local\WavePaintSim_SingleInstance`）。调试时确保只有一个实例。
4. **混淆核心不可改**：所有数据通过 `window.document_wave` / `window.Signal` / `window.mapCanvasPosition` 等全局 API 交互。不要尝试解码混淆代码。
5. **数据模型**：任何创建/修改信号的操作都要遵守 `values.length = m_sampleCount × (m_subStepCount + 1)`，否则绘制/导出/仿真会错位。
6. **位值编码**：Bit 信号 values 是数字（0/1/-1/2/3/4）；Vector 是字符串。写值前用 `toNativeBitValue`（在 sim-bridge.js 里有，feature 模块需自行实现或复制）。
7. **`#sample-spin` / `#substep-spin`**：修改它们会触发原版 resize；如要自定义 resize（F3），用捕获阶段拦截其 change。
8. **ES module 与普通 script 通信**：`sim-bridge.js` 是 module，不暴露到 window；feature 模块如需调用其中函数，需在 sim-bridge.js 里 `window.xxx = fn` 显式暴露，或通过 DOM 事件（`CustomEvent`）。
9. **信号带 y 位置**：实测在画布顶部（y≈0.1×高）。F2 需要精确行内 y 判断，务必实测 `mapCanvasPosition` 行为后再写死逻辑。
10. **不要引入外部依赖**：全部用原生 JS/浏览器 API 实现；不要加 npm 包（应用是离线便携的）。
