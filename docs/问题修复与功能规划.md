## 1. 数据模型速查（必须读，理解一切的前提）

```
document_wave
 ├─ m_sampleCount   : 时间步数（UI "步数" #sample-spin，默认 30）
 ├─ m_subStepCount  : 子步数（UI "子步数" #substep-spin，默认 1，范围 0~16）
 └─ m_signals[]     : Signal 对象

核心规则：每个 Signal 的 values.length = m_sampleCount × (m_subStepCount + 1)
实测：
  步数30 / 子步1 → 长度 60（stride=2）
  步数30 / 子步2 → 长度 90（stride=3）

每个"主步"在 values 中占 stride = (子步+1) 个下标：
  主值下标 = mainStep × stride           （该步的第 1 个值，仿真采样用这个）
  子步下标 = mainStep × stride + 1 .. +stride-1 （子步细分，时钟沿在此）

位值编码（Bit 信号 values 是数字数组）：
  0=低, 1=高, -1=未定义(x), 2=高阻(z), 3=上拉(u), 4=下拉(d)
  Vector 信号 values 是字符串数组（如 "0000" / "xxxx"）

坐标映射（window.mapCanvasPosition(x, y) 返回）关键字段：
  signalIndex      ：第几个信号（-1 = 未命中）
  signalSampleIndex：★ 直接对应 values 下标（点击/绘制写这里）
  mainStep         ：主步号
  signalSubStep    ：子步号（0..stride-1）
  signalDivisor    ：= stride（子步+1）
```

**例**（步数30/子步1，stride=2）：主步2 的两个下标是 4（主值）和 5（子步值）。

## 2. 问题 A：仿真结果一直为 0（严重 bug）

### 2.1 现象

用户反馈：绘制波形后点「Sim」，仿真结果（如 counter 的 q）**一直是 0**，不正确。

### 2.2 根因（已实测确认）

1. `js/sim-bridge.js` 的 `readWaveDocument()`（约 314 行）从画布读信号构造仿真输入时，**只采样每个主步的"主值下标"**：
   ```js
   const stride = canvasSubSteps() + 1;
   const values = Array.from({ length: timeSteps }, (_, cell) => {
     const direct = stride <= 1 ? cell : cell * stride;   // 采 mainStep*stride（偶数下标 0,2,4...）
     const raw = rawValues.length > timeSteps ? rawValues[Math.min(direct, rawValues.length - 1)] : rawValues[cell];
     return width <= 1 ? fromNativeBitValue(raw) : normalizeVectorValue(raw, width);
   });
   ```
   → 只有画在**偶数下标（主值，mainStep×stride）**的值会被仿真读取。

2. `js/feature-draw.js`（TimeGen 绘制，F2）的 `hitTest()` 返回并写入的是 **`m.signalSampleIndex`（鼠标所在下标）**：
   ```js
   return { signalIndex, sampleIndex: idx, value };
   // paintAt: sig.values[hit.sampleIndex] = hit.value;
   ```
   用户点击一个格子时，`signalSampleIndex` 可能是**奇数（子步值）**（如 x=200 → sampleIdx=5）。

3. **结论**：用户画在奇数下标的值，`readWaveDocument` 采不到（它只采偶数主值下标）→ 仿真输入里该步是 x/0 → 仿真结果 0。

### 2.3 修复方案（推荐）

**改 `js/feature-draw.js` 的 `paintAt()`：绘制时写入整个主步的所有 stride 个下标**，即从 `mainStep*stride` 到 `mainStep*stride+stride-1` 全部写入目标值。

这样：
- 主值下标（第 1 个）被写入 → `readWaveDocument` 采样正确 → 仿真结果正确
- 子步下标也写入 → 画布显示整步一致，不出现"半格"怪象

具体修改：

1. `hitTest()` 返回增加 `mainStep` 和 `stride`：
   ```js
   function hitTest(e) {
     const m = wpf.mapAt(e.clientX, e.clientY);
     if (!m || m.clickedOnName) return null;
     const signalIndex = m.signalIndex;
     if (signalIndex < 0 || !isPaintableSignal(m.signal)) return null;
     const sig = window.document_wave.m_signals[signalIndex];
     const idx = m.signalSampleIndex;
     if (idx < 0 || idx >= sig.values.length) return null;
     const stride = Math.max(1, m.signalDivisor || (wpf.subSteps() + 1));
     const mainStep = Math.max(0, m.mainStep);
     // 计算目标值（上半 1 / 下半 0 / Shift 擦除 x）
     const band = wpf.signalRowBand(e.clientX, e.clientY, signalIndex);
     let value;
     if (e.shiftKey) value = -1;
     else if (band && band.height > 0) {
       const canvas = wpf.canvas();
       const yInCanvas = e.clientY - canvas.getBoundingClientRect().top;
       value = (yInCanvas - band.top) < band.height / 2 ? 1 : 0;
     } else {
       value = wpf.bitStateToValue(wpf.currentBitState());
     }
     return { signalIndex, sampleIndex: idx, mainStep, stride, value };
   }
   ```
   > 注：需要 `wpf.subSteps()` —— 若 `feature-common.js` 没有，可自行实现：`Math.max(0, Number(window.document_wave.m_subStepCount) || 0)`。

2. `paintAt()` 改为写整个主步组：
   ```js
   function paintAt(e) {
     const hit = hitTest(e);
     if (!hit) return;
     const sig = window.document_wave.m_signals[hit.signalIndex];
     const start = hit.mainStep * hit.stride;
     const end = Math.min(start + hit.stride - 1, sig.values.length - 1);
     for (let i = start; i <= end; i += 1) sig.values[i] = hit.value;
     // 清时钟标记（如有）
     if (Array.isArray(sig.clockMarkers)) {
       for (let i = start; i <= end; i += 1) if (sig.clockMarkers[i]) sig.clockMarkers[i] = false;
     }
     window.__wpf.cursor = { signalIndex: hit.signalIndex, sampleIndex: start };
     wpf.scheduleRedraw();
   }
   ```

3. `feature-shortcuts.js` 的方向键绘制目前写单个下标 `target.values[nextSample]`——**也改为写主步组**，否则快捷键绘制的值与仿真采样不一致。同样按 `mainStep*stride` 定位。可从 `window.__wpf.cursor` 或 `mapCanvasPosition` 得到 mainStep。

### 2.4 验收标准

- 添加 counter 信号（clk/rst_n/en）→ 用 TimeGen 画笔点任意格子画 clk=0/1 → 点 Sim → **q 不为 0**（随时钟计数增长）。
- 画布的整步显示：点一个格子，该主步的 (stride) 个子格全部变成目标值（视觉整格）。
- 导出 WaveDrom / 生成 TB 时，clk 值序列与画布主值一致。

## 5. 问题 D：拖动编辑锁定信号（TimeGen 行为）

### 5.1 用户反馈（原话归纳）

"波形拖动编辑时，我希望一次鼠标点击下去，无论鼠标移到哪儿，只会影响第一个我选择的这个波形，而不是鼠标移到哪儿就影响哪里的波形。也就是说，需要更像 TimeGen。"

### 5.2 现状（`js/feature-draw.js`）

- `onMouseDown`：mousedown 时 `hitTest(e)` 用**当前鼠标位置**的 `signalIndex`，`paintAt` 写该信号。
- `onMouseMove`：`if (!drag.active) return; paintAt(e);` —— `paintAt` 里 `hitTest(e)` 用**当前鼠标位置**，所以拖动到别的信号行时，会**切换目标信号**（"鼠标移到哪就影响哪"）。

### 5.3 需求行为

- mousedown 时**锁定**目标信号（signalIndex 固定）。
- 之后 mousemove：**只在锁定信号内绘制**，sampleIndex 随 x 变化，但 signalIndex 不变。
- 鼠标拖出信号带/画布：仍只影响锁定信号（可限制在锁定信号行内）。

### 5.4 实现方案（`js/feature-draw.js`）

1. `drag` 对象增加锁定字段：
   ```js
   const drag = { active: false, signalIndex: -1, value: 1 };
   ```
2. `onMouseDown` 中，`hitTest` 后锁定：
   ```js
   if (hit) {
     drag.active = true;
     drag.signalIndex = hit.signalIndex;
     drag.value = hit.value;
     e.stopImmediatePropagation();
     e.preventDefault();
     paintAt(e);   // 首次按下绘制
   }
   ```
3. `paintAt` 拆分：按下时用 hitTest（含信号判定）；移动时**强制用锁定信号**：
   ```js
   function paintMove(e) {
     // 用当前位置只算 sampleIndex / mainStep，但信号用 drag.signalIndex
     const m = wpf.mapAt(e.clientX, e.clientY);
     if (!m) return;
     const sig = window.document_wave.m_signals[drag.signalIndex];
     if (!sig || !isPaintableSignal(sig)) return;
     const stride = Math.max(1, m.signalDivisor || (wpf.subSteps() + 1));
     const mainStep = m.mainStep;           // 拖动到不同行时 mainStep 仍可取
     if (mainStep < 0 || mainStep >= window.document_wave.m_sampleCount) return;
     const start = mainStep * stride;
     const end = Math.min(start + stride - 1, sig.values.length - 1);
     for (let i = start; i <= end; i += 1) sig.values[i] = drag.value;
     window.__wpf.cursor = { signalIndex: drag.signalIndex, sampleIndex: start };
     wpf.scheduleRedraw();
   }
   ```
   `onMouseMove` 改为调用 `paintMove(e)`（不再重新 hitTest 换信号）。
4. 跨行拖动时，`mapCanvasPosition` 的 `mainStep` 在不同 y 是否一致？实测同一 x 不同 y 的 mainStep 相同（x 决定主步）。若不一致，可用按下时的 x 方向换算，或直接按当前 m.mainStep（TimeGen 语义：横向位置决定画到哪一格）。**以实测为准**。
5. `onMouseUp`：`drag.active = false; drag.signalIndex = -1;`。

> 注意：这与"编辑力度（问题 E）"叠加——锁定信号后，绘制的目标格子由力度决定（整步或子步）。

### 5.5 验收

- 在信号 A 上按下，拖到信号 B 行：只改 A，不改 B。
- 拖动横向移动：A 的对应主步被连续绘制。
- 松开后再点信号 B：正常编辑 B。

## 6. 问题 E：编辑力度（粒度）选项规划

### 6.1 用户反馈（原话归纳）

- "现在是因为始终存在上升沿和下降沿，所以编辑的力度其实是一个时钟内有两个这样的力度。"
- "除了时钟之外，其实其他信号只需要一个时钟周期内进行编辑一次即可，我就不用选取两个格子进行编辑了，而是选择一个格子进行编辑。"
- "这个力度的功能力度大小是可调的，请对此做功能规划。"

### 6.2 背景理解（数据模型）

每个主步在 values 中占 `stride = 子步+1` 个下标：
- 时钟信号：stride=2 时每主步有 2 个可编辑点（子步0=主值、子步1=沿），对应上升沿/下降沿 → "一个时钟内有两个力度"。
- 其它信号：通常只需每主步编辑一次（改整个主步），不必分别编辑 2 个子格。

用户希望：**提供一个"编辑力度"选项**，控制一次点击/拖动影响多少个下标：
- **力度 = 整步（每主步 1 个编辑单位）**：点击任意位置 → 写整个主步的 stride 个下标（默认，适合非时钟信号；也符合问题 A 的修复方向）。
- **力度 = 子步（每子格独立）**：点击 → 只写单个下标（适合时钟信号精确编辑上升/下降沿）。
- 力度大小**可调**（可下拉/数字选择，如 1=整步、2=半步等；更通用的表述：一次编辑影响的子格数量）。

### 6.3 功能设计

**UI 位置**：右侧仿真栏顶部（或工具栏位状态选择器旁）加一个下拉/开关：「编辑力度」：
- 选项 A：「整步」（一次编辑一个主步的全部子格）——默认
- 选项 B：「子步」（一次编辑一个子格）
- 可选选项 C：「自由」（默认 = 子步数+1？不，自由=每步所有格）

**状态存储**：`window.__wpf.editGranularity = 'step' | 'substep'`（默认 `'step'`）。存 `localStorage`（key 如 `wpf.editGranularity`）以便重启保持。

**影响范围**：
- `feature-draw.js` 的绘制（问题 A 修复 + 问题 D 锁定的基础上）：
  - `'step'`：写 `[mainStep*stride, mainStep*stride+stride-1]`（整组）
  - `'substep'`：写单个 `signalSampleIndex`
- `feature-shortcuts.js` 的方向键绘制：同样按力度写。
- `feature-select.js` 批量操作：框选已按 sampleStart..sampleEnd 精确操作，不受力度影响（保持）。

**实现要点**：
1. `feature-common.js` 增加：
   ```js
   wpf.editGranularity = function () {
     const v = localStorage.getItem('wpf.editGranularity') || 'step';
     return v === 'substep' ? 'substep' : 'step';
   };
   wpf.setEditGranularity = function (v) {
     localStorage.setItem('wpf.editGranularity', v === 'substep' ? 'substep' : 'step');
   };
   ```
2. `feature-draw.js` 的 `paintAt`/`paintMove` 按 `wpf.editGranularity()` 决定写整组还是单格：
   ```js
   if (wpf.editGranularity() === 'substep') {
     sig.values[hit.sampleIndex] = hit.value;   // 单格
   } else {
     for (let i = start; i <= end; i += 1) sig.values[i] = hit.value; // 整组
   }
   ```
3. UI：在 `index.html` 侧栏顶部加一个小的选择器（如 `select` 或两个小按钮），绑定 `__wpf.setEditGranularity`。样式随侧栏统一（问题 C）。

**注意**：当力度为 `'substep'` 且用户只画了奇数（子步）下标时，`readWaveDocument` 仍只采主值（偶数）→ 仿真可能又是 0。**因此：**
- 默认必须是 `'step'`（整步，保证仿真正确）。
- `'substep'` 模式主要用于时钟信号的沿编辑；若用户要用该模式并仿真，文档应说明：时钟信号建议画主值（偶数下标），或 readWaveDocument 对"该步内全为 x 而子步有值"时回退到子步值（可选增强，见下）。

**可选增强（推荐做，但标为可选）**：`readWaveDocument` 采样增强——对每个主步，若主值下标为 x 但该步内其它下标有确定值，则取该步内第一个确定值：
```js
// 伪代码：cell 主步
const startIdx = cell * stride;
const group = rawValues.slice(startIdx, startIdx + stride);
const mainVal = group[0];
const effective = (mainVal === -1 || mainVal === 'x' || mainVal === undefined)
  ? (group.find(v => v !== -1 && v !== undefined && String(v).trim() !== '') ?? mainVal)
  : mainVal;
```
这样即使用户用子步力度画了值，仿真也能取到。此项增强能彻底消除"仿真 0"隐患。

## 8. 常见坑

1. **csc 是 .NET 4.0（C# 4.0）**：改 `WavePaintLauncher.cs` 禁止 `out int x`、`??=` 等 C#7+ 语法。本次不改 C#，除非必须。
2. **改 JS/HTML 必须重建 exe**，页面刷新不生效。
3. **禁止改混淆核心** `wavepaint.63e6dade.js`；一切通过 `window.document_wave` / `window.mapCanvasPosition` / 事件接管实现。
4. **数据模型**：创建/修改信号必须遵守 `values.length = 步数×(子步+1)`；绘制默认写整主步，保证仿真采样正确。

6. **页面不可见时 requestAnimationFrame 不执行**：feature-measure 的 overlay 依赖 RAF，调试时确保页面可见。
7. **`#sample-spin`/`#substep-spin` 已被 `feature-resize.js` 接管**（change 时智能 resize），不要在别处重复拦截。
8. **`sim-bridge.js` 的 DOM id 不要改**（`#sim-panel`、`#sim-tb`、`#sim-addsignals` 等被 JS 引用），只改样式。
9. **中文编码**：`index.html` 与 `js/*.js` 统一 UTF-8 无 BOM；写入中文用 `[System.IO.File]::WriteAllText(path, text, (New-Object System.Text.UTF8Encoding($false)))`，不要用 `Set-Content`（默认 GBK 会乱码）。
