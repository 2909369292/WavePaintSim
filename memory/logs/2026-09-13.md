## 关键结论
- **主题变量必须抄真机**：原型要「像」，最省事的做法是把 `css/wavepaint.e7b903ef.css` 的 `:root` 变量整段复制，
  而不是自己配色 —— 否则评审时用户会纠结「颜色不对」，淹没对**形态**的判断。
- **类名统一 `mk-` 前缀是硬要求**：原型与真前端**共用同一份 `img/`**、将来还要把结构搬进 `js/sim/dock/*`，
  命名一旦撞车（`.panel`/`.tab`/`.split` 等）就会在接线阶段变成隐性地雷。
- **必须经 `http://` 打开**：`file://` 下 `../img/*.svg` 受同源策略限制，工具栏图标会全丢，看起来像「原型坏了」。
- **真实鼠标拖拽才能验出落点问题**：探针 B 组用 CDP `Input.dispatchMouseEvent` 真拖（非 JS 直接调 API），
  才暴露出「浮窗拖动无落点提示」「`pointerup` 无坐标」两个缺陷 —— 纯 API 调用永远测不到。
- **布局体检（F 组）比功能断言更能发现「丑」**：无横向溢出 / 三段不重叠 / 工作区高度 875 of 1000 /
  四窗格尺寸 / **无裁切文本** / 图片全加载 / 浅色主题生效 —— 这类断言是 UI 原型的「回归网」。

## 本轮原型内修掉的 4 个真缺陷
1. `floatPanel(id, opts)` 忽略 `opts.x/opts.y` → `presetReview` 预置浮窗坐标丢失。**已修**：读取 opts。
2. `applyPreset(name, hard)` 的 `hard` 分支直接 `return presetSim()`、忽略传入预设名 → `__mock.reset()` 与 `Ctrl+Alt+0` 语义混乱。**已修**：统一走 `PRESETS[name]`。
