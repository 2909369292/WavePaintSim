## 做了什么

### Bug1：仿真服务瞬时离线（`js/sim/ui-bridge.js`）

- **根因**：launcher 的 AcceptLoop 异常自愈（RestartServer 同端口重绑，见 P06/#55）会制造
  “服务瞬时不可达”窗口：该窗口内的 `/api/sim` 请求被丢弃，UI 旧实现一律提示
  “请重启应用”——用户以为服务“永久离线”，实际上服务几百 ms 后自己恢复了。
- **修复**：
  - 新增 `probeServerAlive(timeoutMs=800)`：快速 GET `api/ping`（exe 内置服务与
    dev-server 都实现了该路由，WavePaintLauncher.cs:252）区分「进程死」与「自愈窗口」。
  - `/api/sim` 请求挂 45s `AbortController`（`SIM_REQUEST_TIMEOUT_MS`），防 iverilog
    卡死时无限“正在运行...”。
  - 失败分类：fetch/abort/network → 探活；探活成功且未自动重试过 → 静默自动重试一次
    （`simAutoRetried`，用户每次手动点击复位）；探活成功但已重试过 → 提示
    “本地服务在线，但本次请求未完成”（iverilog 超时/请求被丢弃）；
    探活失败 → 保留“请重启应用”指引。
- **验证**：`.e2e-tmp/probe-simfail.mjs` 三场景（S-A selfheal=自动重试 2 次 / S-B dead=
    提示重启 / S-C abort=提示超时）全部 PASS。

### Bug2：添加信号按钮图标消失（`index.html`）

- **根因**（两级）：
  1. 汉化版 CSS 把 `.wp-tutorial-highlight` 与瞬态教程元素一起隐藏
     （`display:none !important`），而教程 JS 恰恰把该 class 标到**真实控件**
     （`#add-signal-btn` / `.tool-btn` / `.dropdown` / 菜单项）上 → 控件被永久隐藏；
  2. 教程在每次启动都隐形重跑（见 Bug3），于是“偶发” = 教程刚好跑到该控件那一刻。
- **修复**：
  - 隐藏列表移除 `.wp-tutorial-highlight`（只隐藏瞬态遮罩/气泡/箭头/进度条）。
  - 新增防御规则：`.tool-btn/.dropdown/.menu-item/.submenu li/input.wp-tutorial-highlight`
    保持 `visibility:visible; pointer-events:auto; animation:none; box-shadow:none`，
    `.tool-btn`/`.dropdown` 再补 display 修正 —— 即使将来教程重跑也不会再藏控件。
- **验证**：`.e2e-tmp/probe-addbtn.mjs`（基线/明暗主题/菜单 5 次循环加信号/窄窗口 440~
    1440/缩放后）ALL PASS；`.e2e-tmp/probe-css.mjs`、`.e2e-tmp/probe-tree.mjs` 辅助定位。

### Bug3：教程隐形重启 + 键盘拦截（`index.html` + `js/editor/file-menu.js`）

- **根因**：exe 每次启动用随机端口 ⇒ Edge 的 localStorage 绑定端口 ⇒ 每会话都是全新
  localStorage ⇒ `wavepaint_tutorial_done` 永不保留 ⇒ 教程每次启动都隐性重跑；它
  （a）在 document 上拦截 Enter/Space/方向键（键盘“失灵”观感），（b）往真实控件挂
  高亮 class（Bug2 触发器），而汉化版把教程 UI 整体隐藏了 → 用户只见副作用不见引导。
- **修复**：
  - `index.html`：在 `<head>` 内联脚本、**核心 `clean.js` 解析前**预置
    `localStorage.wavepaint_tutorial_done='true'`（try/catch 包裹，隐私模式不炸）。
  - `js/editor/file-menu.js`：捕获阶段拦截 `#menu-bar li[data-action="tutorial"]`
    点击 → `collapseMenus()` + `wpAlert` 中文提示“引导教程已在本版本隐藏…”，
    杜绝核心 `removeItem('wavepaint_tutorial_done')+queueTutorial` 重启隐形教程。
- **验证**：`.e2e-tmp/probe-tutorial.mjs` T1（空 localStorage 启动：按钮可见、无高亮、
    无键盘拦截）+ T2（点帮助→教程：弹“教程”中文提示模态、关闭后仍无拦截、done 仍为
    true）ALL PASS。

## 第四轮：#82 遗留 Edge 窗口停在死随机端口 → “直接无法仿真”根治（2026-09-09）

> 用户报障：**存在仿真失败的问题，直接无法仿真**。
> 表面是“仿真功能坏了”，实际是用户正看着的 Edge 页面停在上一个已死实例的随机端口上；
> 该页面同源 `/api/*` 全部断连，所以点「运行仿真」必失败。本轮在 launcher 层根治
> 「死窗口越积越多 + 旧实例永不退出 + 新实例只开窗不收窗」的整条根因链。

## 本轮目标

1. 实证定位“直接无法仿真”的真根因（先排除服务与代码，再看桌面窗口状态）。
2. 修复 launcher：开新窗前自动收拢全部遗留 WavePaint 窗口（只保留新开的那一个）。
3. 真机验证：死窗口 5 → 1、新实例可完整仿真、回归全绿、exe 重建并核验特征串。

## 做了什么

### 排查结论（先实证再动手）

- 当前存活服务（PID 47120，端口 6856，build 2055db3）本身健康：headless Edge 直连
  实测点「运行仿真」成功出 4 个输出信号，无 console 异常、无网络失败 → **不是服务死**。
- 真凶：用户 Edge 窗口地址栏停在 `127.0.0.1:9245` —— 当天 02:59 启动后已退出的旧实例
  （PID 44520）的随机端口；服务死后该页面所有 `/api/*` 断连 → 用户以为“仿真工具坏了”。
- 桌面当时存在 5 个同名「WavePaint 波形编辑」顶层窗口（hwnd 全部挂在 msedge 40436 下）：
  部分指向 6856（活实例）、部分指向 9245/6150（已死实例）。Edge 把同 profile 的
  `--app` 窗口“还原”成一个浏览器进程里的多个 HWND，**无法按进程命令行区分 URL**。
- 根因链：
  1. 重建/崩溃/手动杀 exe 时，其 Edge 窗口（指向当时的随机端口）不会自己消失；
  2. launcher 的 `HasWindow()` 只看 msedge 进程 `MainWindowTitle`，残留任意同名窗口
     就判定“有窗口在服务” → 旧实例永不满足退出条件（需无窗口>12s 且 idle>20s）；
  3. 旧实例不退出 → 旧端口文件残留 + 旧页面继续在桌面 → 死端口窗口越积越多；
  4. `OpenExistingInstance()` 只会新开一个窗口、从不收旧窗口 → 每次重启/重建都累积；
  5. 用户点开其中一个死窗口 → 同源 `/api/*` 全断 → “直接无法仿真”假象。

### 修复（`WavePaintLauncher.cs`，单文件 +80 行）

- 新增 `CloseLegacyWindows()`：
  - `EnumWindows` 枚举全部**可见**顶层窗口，标题含 `WavePaint` / `WaveWorkbench`
    （忽略大小写）者入列；
  - 逐个 `PostMessage(WM_CLOSE)`；随后轮询最多 ~2.5s（500ms×5）等窗口消失，不等也不阻塞；
  - 写一行日志 `CLOSE-LEGACY n window(s)`（`%TEMP%\WavePaintClean_sim.log`）。
- 调用点 1：`MainCore()`（全新启动、单实例互斥体已拿到）`Process.Start(psi)` **之前**；
- 调用点 2：`OpenExistingInstance()`（已有实例在跑、本进程将退出）`Process.Start(psi)`
  **之前**。
- 语义：同一时刻桌面只保留一份指向“最新一次启动”的 WavePaint 页面；死端口页面、
  重复页面、旧构建页面一律先收再开。
- 收尾审查确认：空闲退出阈值（无窗口>24 tick=12s 且 idle>20s）远大于收窗窗口期
  （~2.5s），不会因收旧窗触误退出；BOM（EF BB BF）保留。

### 取舍（详见 `07-DECISIONS.md` D13）

- 接受“再次双击 exe（已有活窗口）会关旧开新”的副作用：若活页上有未保存内容会被关掉。

## 调查结论（先实证）

- 改名对象只可能是**局部绑定标识符**（`_0x…` 是 obfuscator.io 为局部变量/函数生成的

- 直接做「文件内去重替换」会撞上 **JS 词法作用域遮蔽**：同名变量可存在于不同函数、不同

## 做了什么

     位点集合比对（这就是 `verify-bindings.mjs` 的验证口径：同 def 位点分组一致 = 改名后
     不会张冠李戴）。
   - **修了两类误报**：class 声明会同时产生 class 级与类方法级两层绑定（scope 归属要按

2. **语义可读命名策略**（人工规则 + 自动回填）
